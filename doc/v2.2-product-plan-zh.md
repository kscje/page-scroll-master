# v2.2 Navigation Shortcuts & Feedback Update 产品规划

本文档定义 Page Scroll Master v2.2 的整体产品范围。v2.2 在现有顶部、底部跳转和长页面导航能力之上，补充可发现的全局快捷键配置、按屏滚动，以及扩展内建议与问题反馈服务。

## 版本目标

v2.2 聚焦三项能力：

1. 用户可在设置页查看“回到顶部”和“回到底部”的当前 Chrome 全局快捷键，并进入浏览器快捷键管理页自定义。
2. 新增“跳转到上一屏”和“跳转到下一屏”，支持根页面和自定义滚动容器。
3. 在设置页直接提交建议或问题反馈，并由服务端转发到开发者邮箱。

## 非目标

- 不尝试绕过 Chrome 限制，由扩展代码直接写入或强制覆盖全局快捷键。
- 不拦截网页已有的 `PageUp`、`PageDown`、空格键或方向键默认行为。
- 不把按屏跳转实现为自动连续滚动、演示模式或定时滚动。
- 不建设完整反馈管理后台；首版只提供提交、校验、限流、邮件转发和基础日志。
- 不默认上传页面 URL、页面内容、截图、书签或站点使用记录。

## 功能一：自定义顶部和底部快捷键

### 产品目标

让用户无需记忆默认快捷键，并能使用 Chrome 提供的全局快捷键管理能力修改“回到顶部”和“回到底部”的按键组合。

### 平台约束

`manifest.json` 中的 `commands` 只能声明建议默认值。Chrome 不允许扩展通过 JavaScript 任意修改用户的全局命令绑定，因此设置页不能实现普通录入框后直接保存快捷键。

v2.2 采用以下交互：

- 使用 `chrome.commands.getAll()` 读取并展示两个命令的当前绑定。
- 提供“自定义快捷键”按钮，打开 `chrome://extensions/shortcuts`。
- 用户从快捷键管理页返回设置页或重新聚焦窗口时，刷新当前绑定。
- 未绑定命令显示“未设置”，并继续提供快捷键管理入口。
- 保留当前建议默认值：
  - 回到顶部：Windows/Linux `Ctrl+Shift+Up`，macOS `Command+Shift+Up`。
  - 回到底部：Windows/Linux `Ctrl+Shift+Down`，macOS `Command+Shift+Down`。

### 设置页建议结构

```text
全局滚动快捷键

回到顶部        Ctrl+Shift+Up
回到底部        Ctrl+Shift+Down

[自定义快捷键]
快捷键由 Chrome 管理，修改后返回本页即可查看最新绑定。
```

### 行为规则

- 快捷键仍由 `background.js` 接收并转发给当前活动标签页。
- 普通网页、SPA 和自定义滚动容器继续复用现有顶部、底部滚动逻辑。
- `chrome://`、新标签页等内容脚本不可运行页面静默忽略，不产生未处理错误。
- 设置页中的悬停隐藏按键配置与 Chrome 全局滚动快捷键是两套独立设置，不合并存储。
- 不新增 Chrome 权限。
- 所有支持语言都应覆盖命令名称、当前绑定、未设置状态、管理入口和说明文案。

### 验收标准

- 设置页能显示 Chrome 当前保存的顶部、底部快捷键。
- 修改快捷键后重新聚焦或刷新设置页可以看到最新绑定。
- 命令未绑定时显示明确状态，不显示错误或虚假的默认绑定。
- 修改后的快捷键可以触发现有顶部、底部跳转。
- 两个命令在根页面和自定义滚动容器中行为一致。
- 不覆盖网页普通按键事件，不新增权限。

## 功能二：跳转到上一屏和下一屏

### 产品目标

用户阅读长页面时，可以按当前可视区域为单位向前或向后移动，无需直接跳到页面顶部、底部或精确拖动滚动条。

### 入口与默认体验

- 在现有浮动按钮组中提供可选的“上一屏”和“下一屏”按钮。
- 两个按钮作为一组启用或关闭，默认关闭，避免改变升级用户当前的双按钮体验。
- 设置页提供详细配置；是否按当前主域名启用由 Popup 管理。
- Popup 在现有高级功能区域新增“按屏跳转”开关。
- 新增两个 Chrome 命令，允许用户在 `chrome://extensions/shortcuts` 中为上一屏、下一屏分配全局快捷键。
- 新命令默认不预设快捷键，避免与网页、浏览器和现有顶部、底部命令冲突。
- 上一屏和下一屏按钮分别支持自定义背景颜色，不强制共用同一颜色。
- 按屏按钮使用独立的“视口 + 方向箭头”图标，不复用顶部、底部按钮的可选箭头图标集。

### 按钮顺序与位置

按屏按钮不提供独立的左侧、右侧、顶部或底部位置配置，而是加入现有主按钮组，并固定放在顶部、底部按钮之间：

```text
回到顶部
上一屏
纵向页面进度按钮（启用时）
下一屏
回到底部
页面中部阅读工具（配置为“页面中部”时）
```

滚动位置书签和智能段落跳转不再允许插入上/下主按钮之间。纵向页面进度按钮继续保留现有按钮组内位置；页面中部阅读工具统一排列在“回到底部”按钮之后。

按钮组整体继续使用现有左侧/右侧、顶部/居中/底部、边缘距离和按钮间距设置。上一屏和下一屏不新增独立位置或独立间距字段，避免产生不可预测的交错和重叠组合。

### 颜色配置

上一屏和下一屏按钮分别配置背景颜色：

```js
previousScreenButtonColor: '#4A9EDD',
nextScreenButtonColor: '#4A9EDD'
```

颜色规则：

- 两个颜色字段彼此独立，设置页分别提供颜色选择器和十六进制输入框。
- 默认值均为 `#4A9EDD`，保持首次启用时与当前主按钮视觉一致。
- 修改其中一个颜色不得覆盖另一个按钮颜色。
- 禁用状态降低按钮整体透明度，不改写用户保存的颜色值。
- 按钮文字和图标颜色使用独立的高对比度前景色，不复用顶部、底部按钮的自定义图标颜色。
- 设置页预览应实时显示两个按钮各自的背景颜色。

### 专用图标

按屏按钮必须使用与“回到顶部/回到底部”明显不同的专用 SVG 图标：

- 上一屏：矩形视口轮廓内包含向上移动箭头。
- 下一屏：矩形视口轮廓内包含向下移动箭头。
- 视口轮廓表达“一屏”的范围，箭头表达移动方向。
- 不使用带顶线/底线的终点箭头，避免被理解为回到页面顶部或底部。
- 不跟随 `iconCustomization.iconSet` 切换，不允许选择现有默认箭头、三角形、折线箭头或双箭头。
- 两个图标使用同一视觉语言和线条粗细，只改变箭头方向。
- SVG 使用 `currentColor`，由按屏按钮自身的高对比度前景色控制。
- 图标必须提供独立的本地化 `aria-label` 和 `title`。

建议图标语义：

```text
┌─────┐   ┌─────┐
│  ↑  │   │  ↓  │
│ ─── │   │ ─── │
└─────┘   └─────┘
 上一屏     下一屏
```

实际 SVG 应保持简洁，在最小 `10px` 按钮尺寸下仍能辨认视口轮廓和方向；默认 `40px` 尺寸下不得与顶部、底部图标混淆。

### 滚动距离

每次跳转距离基于当前主要滚动容器的可视高度：

```js
const viewportHeight = isRootScrollContainer(container)
  ? window.innerHeight
  : container.clientHeight;
const step = viewportHeight * screenStepRatio;
const targetTop = clamp(currentTop + direction * step, 0, maxScrollTop);
```

默认 `screenStepRatio` 为 `0.9`，保留约 10% 的上下文重叠，范围为 `0.5-1.0`。

### 行为规则

- 复用 `document.scrollingElement`、候选容器评分和根元素回退逻辑，不假设 `window` 是滚动容器。
- 复用现有 `smoothScrollTo()` 和滚动速度设置。
- 上一屏在页面顶部禁用，下一屏在页面底部禁用。
- 动态内容导致高度变化时，每次点击或命令触发都重新计算可视高度和最大滚动位置。
- 新的按屏跳转应取消尚未完成的旧滚动动画。
- 输入框、文本框、可编辑区域获得焦点时，不处理内容脚本级按键监听；Chrome 全局命令仍按浏览器规则触发。
- 站点总开关关闭时不创建按屏按钮或监听器。
- 按屏功能关闭或站点状态变化时，立即清理对应 DOM 和状态。
- 全屏隐藏、按钮尺寸、形状、间距、透明度和页面边缘位置复用现有按钮体系。
- 上一屏、下一屏背景颜色使用各自设置；专用按屏图标不读取现有顶部、底部图标样式或图标颜色设置。

### 设置结构建议

详细参数保存在 `chrome.storage.sync`：

```js
advancedSettings: {
  screenNavigation: {
    screenStepRatio: 0.9,
    previousScreenButtonColor: '#4A9EDD',
    nextScreenButtonColor: '#4A9EDD'
  }
}
```

主域名启用状态保存在 `chrome.storage.local`：

```js
domainFeatureStates: {
  'example.com': {
    extensionEnabled: true,
    features: {
      screenNavigation: true
    }
  }
}
```

兼容规则：

- 旧用户没有 `screenNavigation` 字段时默认关闭。
- 旧设置通过深合并获得 `screenStepRatio: 0.9` 和两个独立的默认按钮颜色。
- 主域名记录缺少该功能字段时默认关闭。
- 不要求用户清空或迁移现有 storage。

### 设置页建议结构

```text
按屏跳转
启用状态：请在工具栏 Popup 中按当前主域名设置

每次滚动距离
[ 90% ] 当前可视区域高度

上一屏按钮颜色
[ #4A9EDD ]

下一屏按钮颜色
[ #4A9EDD ]

快捷键
上一屏：未设置
下一屏：未设置
[自定义快捷键]
```

### 验收标准

- 根页面和自定义滚动容器均按各自可视高度滚动。
- 默认 90% 步长保留可辨认的阅读上下文。
- 接近顶部或底部时正确限制目标位置，不发生越界或反向跳动。
- 点击按钮和 Chrome 命令复用相同滚动实现。
- SPA、动态内容和滚动容器重新解析后仍使用当前有效容器。
- 重复启停不产生重复按钮、监听器或滚动动画。
- 功能默认关闭，升级后不改变现有按钮布局。
- 上一屏和下一屏颜色可以分别保存、加载和实时预览，修改时互不覆盖。
- 按屏按钮始终使用专用“视口 + 方向箭头”图标，不受顶部、底部图标样式设置影响。
- 在最小和最大按钮尺寸下，专用图标仍可辨认且不会溢出按钮。
- Options 预览和真实页面按钮顺序、尺寸、颜色、图标及间距一致。

## 功能三：服务端建议与反馈提交

反馈服务的产品边界、推荐架构、表单字段和隐私要求以 `doc/advanced-features-development-guide-zh.md` 中的“v2.2 功能：服务端建议&反馈提交模块”为准。

v2.2 首版包括：

- 设置页反馈类型、反馈内容和可选联系方式。
- 用户主动选择图片，最多 3 张，每张不超过 5MB。
- 反馈表单不读取或发送当前页面 URL 和浏览器语言。
- Cloudflare Worker 服务端校验、限流、反垃圾和基础日志。
- Resend 或同类邮件服务转发。
- 明确的提交中、成功、失败和重试状态。
- 限定到反馈服务域名的最小网络权限。
- 隐私政策和 Chrome Web Store 数据披露同步更新。

## 优化调整：阅读工具按钮位置简化

### 调整目标

降低顶部、底部、上一屏、下一屏、纵向页面进度和阅读工具同时启用时的按钮组复杂度，避免滚动位置书签和智能段落跳转被夹在多个方向按钮之间。

本调整只影响以下两个独立阅读工具按钮：

- 滚动位置书签按钮。
- 智能段落跳转按钮。

纵向页面进度按钮不属于本调整范围，仍可保留在主滚动按钮组中。

### 可选位置

两个阅读工具按钮的位置选项统一调整为：

```js
buttonPosition: 'pageTop' | 'pageBottom' | 'pageMiddle'
```

- `pageTop`：固定在页面同侧顶部区域。
- `pageBottom`：固定在页面同侧底部区域。
- `pageMiddle`：加入页面中部的主按钮组合区域，但排列在“回到底部”按钮之后，不插入回到顶部、上一屏、下一屏、回到底部之间。

移除：

```js
buttonPosition: 'betweenScrollButtons'
```

设置页不再显示“上/下按钮之间”选项，改为“页面中部”。

### 页面中部顺序

当两个阅读工具都选择 `pageMiddle` 时，固定顺序为：

```text
回到顶部
上一屏（启用时）
纵向页面进度按钮（启用时）
下一屏（启用时）
回到底部
滚动位置书签
智能段落跳转
```

规则：

- 阅读工具始终位于“回到底部”按钮之后。
- 滚动位置书签固定排在智能段落跳转之前。
- 未启用或不在 `pageMiddle` 的工具不占位置。
- 不提供用户自定义排序，避免 Options 预览和真实页面出现不同排列。
- 阅读工具使用现有 `buttonSpacing` 与相邻按钮保持间距，不新增工具专属间距字段。
- 如果两个阅读工具分别选择不同位置，则各自在页面顶部、底部或中部区域独立布局。

### 顶部和底部区域

- `pageTop` 和 `pageBottom` 继续使用现有边缘距离与同侧自动避让规则。
- 多个工具选择同一顶部或底部区域时，固定按滚动位置书签、智能段落跳转的顺序堆叠。
- 顶部或底部阅读工具不跟随主按钮组的垂直对齐，不插入主按钮内部。
- 主按钮组位置不因顶部或底部阅读工具出现而改变；发生同侧重叠风险时，由阅读工具向页面内部避让。

### 旧设置迁移

v2.2 读取旧设置时进行兼容迁移：

```js
if (buttonPosition === 'betweenScrollButtons') {
  buttonPosition = 'pageMiddle';
}
```

- 迁移后工具显示在“回到底部”按钮之后。
- 不要求用户清空 `chrome.storage.sync`。
- 新保存的数据只写入 `pageTop`、`pageBottom` 或 `pageMiddle`。
- Options、内容脚本和测试夹具必须使用同一规范化 helper，避免旧值在不同路径中产生不同布局。

### 设置页建议结构

```text
滚动位置书签按钮位置
( ) 页面顶部
(•) 页面底部
( ) 页面中部

智能段落跳转按钮位置
( ) 页面顶部
(•) 页面底部
( ) 页面中部
```

说明文案：

> 页面中部会将阅读工具排列在“回到底部”按钮之后，不会夹在滚动方向按钮之间。

### 验收标准

- 两个阅读工具的设置中不再出现“上/下按钮之间”。
- 页面中部工具始终位于“回到底部”按钮之后。
- 两个工具同时位于页面中部时，书签在前、智能段落跳转在后。
- 上一屏、下一屏和纵向页面进度动态启停时，阅读工具仍保持在主方向按钮之后。
- 旧 `betweenScrollButtons` 设置自动迁移为 `pageMiddle`，且不丢失其他详细参数。
- 页面顶部、底部和中部布局不会互相重叠或改变主按钮组定位。
- Options 预览与真实页面的按钮顺序、间距和动态启停结果一致。

## v2.2 完成定义

v2.2 只有在以下条件满足时才算完成：

- 用户可以查看并通过 Chrome 快捷键管理页修改顶部、底部命令绑定。
- 上一屏、下一屏在根页面和自定义滚动容器中行为正确。
- 新功能默认关闭并兼容旧用户存储及主域名状态。
- Popup、Options 预览、真实页面和全局命令状态保持一致。
- 反馈服务满足主动提交、最小权限和隐私披露要求。
- 所有支持语言文案完整。
- 对应 Node 回归、真实 Chrome 快捷键和页面交互验收通过。
