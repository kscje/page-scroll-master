# v2.5 Compatibility Update 产品规划

本文档定义 Page Scroll Master v2.5 的规划范围。v2.5 聚焦“兼容性增强”的最小可用版本：提高现有滚动能力在复杂网页中的稳定性，并提供一个用户可自助的站点级兜底模式。

## 版本目标

v2.5 聚焦三项能力：

1. 增强主要滚动容器检测，降低误选侧栏、代码块、小面板、弹窗或工具栏的概率。
2. 将滚动容器重新评分改为事件驱动，避免在高频滚动、自动滚屏帧循环或普通点击操作中重复扫描 DOM。
3. 新增站点级兼容模式，让用户在自动检测失败时可手动切换到页面根滚动兜底。

该版本不是新阅读功能版本。顶部/底部跳转、按屏跳转、页面进度条、滚动位置书签、智能段落跳转和自动滚屏的功能边界保持不变。

## 非目标

- 不支持跨域 iframe 内部内容。
- 不读取 closed Shadow DOM。
- 不支持 `chrome://`、Chrome Web Store 页面等内容脚本不可注入页面。
- 不新增远程站点规则库。
- 不新增 Chrome 权限、远程请求、匿名统计字段或自动兼容性上报。
- 不做大规模设置页 UI 改版。
- 不在 v2.5 首版实现完整的 `largest` / `mainContent` 四档策略。
- 不在 v2.5 首版强制加入本地诊断信息面板。

## 功能一：滚动容器检测增强

### 产品目标

让插件在文档、Wiki、知识库、后台长页面、SPA 和自定义滚动容器页面中更稳定地选中主阅读区域，而不是误选页面局部可滚动组件。

### 现有基础

当前 `content.js` 已有以下基础：

- `findScrollContainer()` 遍历根滚动元素和常见候选元素。
- `scoreScrollContainer()` 结合滚动范围、可视面积、语义标签和角色评分。
- `detectAndUpdateScrollContainer()` 在 SPA 和动态 DOM 场景下重新检测容器。
- 进度条、按屏跳转、目录、书签和自动滚屏均依赖当前主要滚动容器。

v2.5 应在现有逻辑上小步增强，不重写整套容器系统。

### 评分规则方向

评分函数继续使用加权累加，但新增或调整规则必须以测试锁定行为。

优先增强：

- 主内容正向信号：`main`、`article`、`[role="main"]`、`[role="document"]`、大可视面积、较长滚动范围。
- 局部组件负向信号：`nav`、`aside`、`header`、`footer`、工具栏、弹窗、小型列表、代码块。
- 面积判断使用相对视口面积比，而不是固定像素阈值。
- 小面积可滚动代码块不应战胜主内容容器。
- 侧栏和主内容同时可滚动时，应优先主内容。

避免：

- 只用绝对像素面积判断“小容器”。
- 为某个网站硬编码域名规则。
- 一次性大幅改变所有权重。
- 为了新增场景牺牲已验证的 Notion、飞书、语雀、钉钉文档等文档类 SPA 兼容性。

### 开发纪律

评分函数属于核心运行时逻辑，调整必须分步验证：

1. 先新增失败用例和已知良好场景基线。
2. 每新增或调整一类评分规则，就单独运行相关测试。
3. 阶段性调整完成后，再运行完整相关回归。
4. 如果容器排序发生回退，应定位到最近一条评分规则，而不是在一批权重变化中倒查。

这样可以避免多个权重叠加后才发现 Notion、飞书等已验证场景回退，却难以判断是哪条规则导致。

## 功能二：事件驱动的容器重新评分

### 产品目标

减少无意义 DOM 扫描，避免兼容性增强与性能体检、卡顿优化目标冲突。

### 行为规则

普通操作应优先复用缓存容器：

- 顶部/底部按钮点击。
- Chrome 快捷键触发。
- 按屏跳转。
- 页面进度条点击跳转。
- 滚动位置书签保存与恢复。
- 智能段落跳转。
- 自动滚屏开始。

这些操作前可以进行轻量有效性校验：

- 缓存容器是否仍存在。
- 缓存容器是否仍在当前文档中。
- 缓存容器是否仍具备可滚动范围。

只有在以下事件发生时才重新评分：

- `MutationObserver` 检测到当前容器被移除或替换。
- SPA 路由变化。
- 延迟加载后首次出现更可信的主容器。
- 站点级兼容模式变化。
- 当前缓存容器轻量校验失败。

自动滚屏的 `requestAnimationFrame` 循环中不得触发完整容器重新评分。

### 与现有功能联动

- 容器被替换后，自动滚屏应停止，避免继续操作失效节点。
- 页面进度条应重新绑定当前有效容器。
- 目录快照应失效并可重建。
- 按屏跳转和顶部/底部跳转应使用当前有效容器。
- 重复启停不应产生重复 DOM、重复监听器或重复动画循环。

## 功能三：站点级兼容模式

### 产品目标

当自动检测无法正确选择滚动区域时，用户可以在设置页为当前主域名切换兼容模式，自助恢复基础滚动能力。

### v2.5 首版模式

v2.5 首版只实现两档：

```text
auto   自动检测，默认值
page   强制使用页面根滚动
```

暂不实现：

```text
largest      强制使用最大可滚动区域
mainContent  偏向主内容区域
```

`largest` 和 `mainContent` 本质上仍是评分算法的不同倾向。v2.5 应先把自动检测本身做好，并提供 `page` 作为最常见极端失败场景的兜底。

### 存储结构

兼容模式应并入现有 `domainFeatureStates`，不新开 storage key。

建议结构：

```js
domainFeatureStates: {
  'example.com': {
    extensionEnabled: true,
    containerStrategy: 'auto',
    features: {
      progressBar: false,
      screenNavigation: false,
      scrollBookmarks: false,
      outlineNavigation: false,
      autoScroll: false
    }
  }
}
```

兼容规则：

- 旧用户缺少 `containerStrategy` 时视为 `auto`。
- 无效值回退到 `auto`。
- 复用现有主域名归一化和迁移路径。
- 不迁移到 `chrome.storage.sync`。
- 不改变旧版 `enableStates` 到 `domainFeatureStates` 的迁移语义。

### 设置页入口

兼容模式入口放在设置页高级兼容区或站点管理相关区域，不放入 Popup。

原因：

- Popup 职责保持为当前主域名总开关和高级功能开关。
- 兼容模式属于低频排障设置，不应增加 Popup 复杂度。
- 设置页更适合展示解释文案和风险提示。

建议文案方向：

```text
滚动容器兼容模式
自动检测：适合大多数页面。
页面根滚动：当按钮无效、进度不动或误控制侧栏时可尝试。
```

切换后应通知当前标签页刷新容器策略，并触发一次事件驱动的重新解析。

## 可选功能：本地诊断信息

本地诊断信息不进入 v2.5 必做范围。若实现，必须满足以下边界：

- 只在用户主动点击“生成诊断信息”时读取并拼装。
- 不在后台预计算。
- 不自动存储。
- 不自动上传。
- 复制前让用户能看到诊断内容。
- 若包含 URL、标题、选择器、检测结果或容器信息，隐私文档需补充说明。

该能力主要提升反馈质量和后续排查效率，不是 v2.5 最小可用兼容增强的必要条件。`auto` / `page` 两档兼容模式已提供基本用户自助路径。

## 测试矩阵

v2.5 应优先扩展 `tests/test-scroll-container-detection.js`，再调整运行时逻辑。

必须覆盖：

- 根页面滚动。
- 主内容容器滚动。
- 侧栏和主内容同时可滚动时选主内容。
- 代码块可滚动但不抢主容器。
- 弹窗、小面板或工具栏不抢主容器。
- SPA 主容器延迟出现。
- SPA 主容器被替换。
- 当前缓存容器被移除后重新解析。
- `auto` 模式使用自动检测结果。
- `page` 模式强制使用页面根滚动。

相关回归：

- `node tests/test-scroll-container-detection.js`
- `node tests/test-content-enable-state.js`
- `node tests/test-progress-bar.js`
- `node tests/test-options-page.js`
- `node tests/test-domain-management.js`

仅修改规划文档时不需要运行上述代码测试；实现阶段按改动范围逐步执行。

## 建议实施顺序

1. 扩展滚动容器检测测试，建立失败用例和已知良好场景基线。
2. 在测试保护下小步调整 `scoreScrollContainer()` 和候选过滤逻辑。
3. 引入缓存容器轻量有效性校验，限制完整重新评分的触发条件。
4. 将 `containerStrategy: 'auto' | 'page'` 并入 `domainFeatureStates`。
5. 在设置页增加站点级兼容模式入口。
6. 将兼容模式变化通知内容脚本，并触发一次重新解析。
7. 补齐 README、CHANGELOG 和发布检查清单中的 v2.5 描述。

## 验收标准

- 自动检测在根页面、主内容容器、自定义滚动容器和 SPA 场景下稳定工作。
- 侧栏、代码块、小面板、弹窗或工具栏不轻易战胜主内容容器。
- 普通按钮点击、快捷键、进度跳转、书签恢复和自动滚屏开始不触发无条件完整 DOM 评分扫描。
- 自动滚屏帧循环中不进行完整容器重新评分。
- 容器被移除、替换或 SPA 路由变化后，相关功能重新绑定或安全停止。
- 用户可按主域名将兼容模式从 `auto` 切换为 `page`。
- 旧用户升级后默认仍为 `auto`，不改变现有体验。
- 兼容模式存储在 `domainFeatureStates` 中，不新增 storage key。
- 不新增权限、远程请求、远程兼容性上报或隐私披露义务。
- 对应 Node 回归测试和 `git diff --check` 通过。

## v2.5 完成定义

v2.5 只有在以下条件满足时才算完成：

- 测试矩阵覆盖主要兼容性失败模式。
- 容器评分增强以小步验证方式完成，没有破坏已验证的文档类 SPA 场景。
- 容器重新评分由事件驱动，不与性能和卡顿优化目标冲突。
- 站点级 `auto` / `page` 兼容模式可保存、加载、切换并作用于当前页面。
- 所有实现保持现有权限、隐私和存储边界。
