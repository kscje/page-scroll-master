# v2.1 Privacy-Friendly Usage Analytics 子模块实施计划

本文档用于指导后续按步骤实现 v2.1 匿名使用统计子模块。v2.1 的整体产品范围和其他功能实施顺序以 `doc/v2.1-product-plan-zh.md` 为准。执行前应确认 v2.0 已完成或已明确跳过；如果 v2.0 尚未实现，统计字段应只接入当前已存在功能，避免为未实现功能预留运行时代码。

> 完成状态（2026-06-14）：客户端本地聚合、设置快照 allowlist、payload 安全审计、设置页同意与预览、可选权限、6 小时上传调度、16KB 请求限制和有界重试已实现。独立 Cloudflare Worker + D1 后端已部署到 `https://page-scroll-master-analytics.kscje-apps.workers.dev/v1/events`，包含严格 schema 校验、批次去重和聚合保留清理。中英文隐私政策、商店说明和发布检查表已同步更新；真实 Chrome Network 验证和 Chrome Web Store 后台数据披露复核均已完成。

## 开发总原则

- 先实现隐私边界和开关，再接事件。
- 默认关闭，不同意不记录、不上传。
- 先本地聚合，再批量上传。
- 事件 schema 使用 allowlist，不允许动态透传对象。
- 所有字段必须经过脱敏和枚举化。
- 每个阶段完成后运行相关测试和 payload 审计。

## 阶段 0：确认合规和服务端方案

### 目标

在写代码前确认统计端点、披露口径和保留策略。

### 任务

1. 重新核对 Chrome Web Store 最新用户数据政策。
2. 确认是否使用自有 HTTPS 端点。
3. 确认不接入远程 JS SDK。
4. 确认服务端不会将 IP、User-Agent 或请求头用于用户画像。
5. 确认原始事件和日志保留期。

### 验收

- 有明确的 HTTPS endpoint。
- 有明确的数据保留策略。
- 有发布前隐私政策更新清单。

## 阶段 1：设置结构和 UI 开关

### 目标

在设置页提供用户可理解、可关闭的匿名统计开关。

### 任务

1. 在 `chrome.storage.local` 中新增设备级 consent：

```js
analyticsConsent: {
  enabled: false,
  policyVersion: 2
}
```

2. 没有该记录或 `policyVersion` 不匹配时一律视为关闭。
3. 在设置页新增开关、说明文案和“查看待发送数据”：

```text
发送匿名使用统计
帮助改进功能优先级。仅发送功能开关、设置选项和按钮点击次数；不会收集访问网址、页面标题、页面内容或个人信息。
```

4. 增加多语言 key，至少覆盖当前已有语言。
5. 开关立即生效，不依赖设置页“保存”按钮。
6. 从 `true` 变为 `false` 时通知 background 清理聚合并撤销可选统计域名权限。

### 验收

- 新安装默认关闭。
- 升级用户默认关闭。
- 设置页文案明确说明收集和不收集的内容。
- 关闭开关后本地队列被清理。

## 阶段 2：建立事件 schema allowlist

### 目标

建立只允许固定字段的事件创建入口，避免误传页面信息。

### 任务

1. 新增事件名 allowlist：

```js
const ANALYTICS_EVENTS = {
  SETTINGS_SNAPSHOT: 'settings_snapshot',
  DAILY_ACTION_COUNTS: 'daily_action_counts',
  DAILY_TOGGLE_COUNTS: 'daily_toggle_counts'
};
```

2. 为每类事件写独立 builder：

```js
buildSettingsSnapshot(settings)
buildDailyActionCounts(date, counters)
buildDailyToggleCounts(date, changes)
```

3. builder 只返回 allowlist 字段。
4. 增加 `assertAnalyticsPayloadIsSafe(payload)` 测试辅助函数。

### 验收

- 事件无法携带任意 payload。
- 测试确认 payload 不含 URL、hostname、title、referrer、text、selector。
- 数值设置已转成区间。

## 阶段 3：本地聚合点击计数

### 目标

统计上下按钮和高级跳转行为，但不记录页面上下文。

### 任务

1. 在用户点击顶部、底部、进度跳转、书签保存/恢复和目录操作时增加本地计数。
2. 当前 Popup 没有顶部/底部跳转按钮，不新增或统计不存在的操作。
3. 快捷键触发计入对应聚合字段。
4. 计数按 UTC 日期聚合。
5. content script 通过 `chrome.runtime.sendMessage` 发送安全事件名，不发送 URL。
6. background 在同意开启时才写入 `chrome.storage.local`。

建议计数字段：

```js
{
  floatingTopClicks,
  floatingBottomClicks,
  progressJumpClicks,
  keyboardTopCommands,
  keyboardBottomCommands,
  bookmarkSaveClicks,
  bookmarkRestoreClicks,
  outlineOpenClicks,
  outlineJumpClicks
}
```

### 验收

- 未开启统计时点击不写队列。
- 开启统计后只增加日级计数。
- 计数记录不包含站点信息。

## 阶段 4：设置快照和功能开关事件

### 目标

获得设置分布和高级功能开关操作趋势。

### 任务

1. 开启匿名统计后发送一次设置快照。
2. 保存设置后发送一次设置快照。
3. Popup 和域名管理中的功能开关变化写入 `daily_toggle_counts`。
4. 每天最多自动发送一次设置快照。

字段转换规则：

- `buttonSize` 转为 `small | medium | large | extraLarge`。
- `buttonSpacing` 转为 `compact | normal | loose`。
- `edgeDistance` 转为 `near | standard | far`。
- `opacity` 转为 `low | medium | high | solid`。
- 自定义颜色只记录 `customColorUsed: true/false`，不记录色值。

### 验收

- 可以计算页面进度条开启/关闭操作趋势。
- 可以计算按钮布局和尺寸偏好。
- 不上传精确颜色值或站点级禁用列表。

## 阶段 5：队列、重试和上传

### 目标

可靠上传聚合事件，并在失败时安全降级。

### 任务

1. 在 `background.js` 中实现队列：

```js
enqueueAnalyticsEvent(event)
flushAnalyticsQueue()
clearAnalyticsQueue()
```

2. 仅保留最近 7 个 UTC 日，不保存逐次事件。
3. 单次请求体上限 16KB。
4. 使用 `fetch()` POST 到固定 HTTPS endpoint。
5. 不设置包含页面来源的 header。
6. 不从 content script 直接请求统计 endpoint。

### 验收

- endpoint 不可用时插件功能不受影响。
- 队列不会无限增长。
- 关闭统计会清空队列并停止重试。

## 阶段 6：Manifest 和权限

### 目标

只增加最小必要网络权限。

### 任务

1. 在 `manifest.json` 中新增固定统计域名 `https://page-scroll-master-analytics.kscje-apps.workers.dev/*` 的 `optional_host_permissions`。
2. 不新增 `<all_urls>` 网络请求权限。
3. 开启统计时由用户手势触发 `chrome.permissions.request()`；拒绝后保持关闭。
4. 关闭统计时撤销可选权限。
5. 检查 CSP 仍不允许远程脚本。
6. 如果统计域名未确定，不加入占位权限、`fetch()`、`alarms` 或上传重试。

### 验收

- 权限解释能通过商店审核。
- 统计端点权限范围最小。

## 阶段 7：隐私政策和商店资料

### 目标

确保实际行为与披露完全一致。

### 任务

1. 更新 `chrome-web-store/privacy/en.md`。
2. 更新 `chrome-web-store/privacy/zh-CN.md`。
3. 更新 `chrome-web-store/listing-content.md` 的隐私说明。
4. 更新 `chrome-web-store/publish-checklist.md` 发布前检查项。
5. Chrome Web Store 后台选择对应数据使用披露。

隐私政策必须说明：

- 统计默认关闭。
- 用户主动开启后才发送。
- 收集功能开关、设置选项、聚合点击次数。
- 不收集访问网址、页面标题、页面内容、个人信息。
- 如何关闭统计。
- 数据保留期和联系邮箱。

### 验收

- 文档不再声称“没有任何外部网络请求”，除非统计模块未上线。
- 商店后台披露与代码行为一致。

## 阶段 8：测试和审计

### 目标

用自动化测试防止后续误传敏感数据。

### 必测项

- 默认关闭时无统计队列、无网络请求。
- 开启后才创建队列。
- 关闭后清空队列。
- 所有 builder 输出字段符合 allowlist。
- payload 中不出现以下字段名或值：

```text
url
uri
origin
host
hostname
domain
title
referrer
text
html
selector
query
hash
pathname
```

- 点击计数按日聚合。
- 设置数值已转为区间。
- 上传失败不会影响滚动功能。
