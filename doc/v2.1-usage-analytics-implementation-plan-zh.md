# v2.1 Privacy-Friendly Usage Analytics 实施计划

本文档用于指导后续按步骤实现 v2.1 匿名使用统计模块。执行前应确认 v2.0 已完成或已明确跳过；如果 v2.0 尚未实现，v2.1 的统计字段应只接入当前已存在功能，避免为未实现功能预留运行时代码。

## 开发总原则

- 先实现隐私边界和开关，再接事件。
- 默认关闭，不同意不记录、不上传。
- 先本地聚合，再批量上传。
- 事件 schema 使用 allowlist，不允许动态透传对象。
- 所有字段必须经过脱敏和枚举化。
- 每个阶段完成后运行相关测试和 payload 审计。

## 阶段 0：确认合规和服务端方案

### 目标

在写代码前确认统计端点、披露口径和保留策略。

### 任务

1. 重新核对 Chrome Web Store 最新用户数据政策。
2. 确认是否使用自有 HTTPS 端点。
3. 确认不接入远程 JS SDK。
4. 确认服务端不会将 IP、User-Agent 或请求头用于用户画像。
5. 确认原始事件和日志保留期。

### 验收

- 有明确的 HTTPS endpoint。
- 有明确的数据保留策略。
- 有发布前隐私政策更新清单。

## 阶段 1：设置结构和 UI 开关

### 目标

在设置页提供用户可理解、可关闭的匿名统计开关。

### 任务

1. 在默认设置中新增：

```js
analytics: {
  enabled: false
}
```

2. 更新设置合并逻辑，旧用户升级后默认补齐 `analytics.enabled = false`。
3. 在设置页新增开关和说明文案：

```text
发送匿名使用统计
帮助改进功能优先级。仅发送功能开关、设置选项和按钮点击次数；不会收集访问网址、页面标题、页面内容或个人信息。
```

4. 增加多语言 key，至少覆盖当前已有语言。
5. 保存设置时，如果从 `true` 变为 `false`，通知 background 清理队列。

### 验收

- 新安装默认关闭。
- 升级用户默认关闭。
- 设置页文案明确说明收集和不收集的内容。
- 关闭开关后本地队列被清理。

## 阶段 2：建立事件 schema allowlist

### 目标

建立只允许固定字段的事件创建入口，避免误传页面信息。

### 任务

1. 新增事件名 allowlist：

```js
const ANALYTICS_EVENTS = {
  SETTINGS_SNAPSHOT: 'settings_snapshot',
  SCROLL_ACTION_COUNT: 'scroll_action_count',
  FEATURE_TOGGLE_CHANGE: 'feature_toggle_change',
  EXTENSION_ERROR_COUNT: 'extension_error_count'
};
```

2. 为每类事件写独立 builder：

```js
buildSettingsSnapshot(settings)
buildScrollActionCount(date, counters)
buildFeatureToggleChange(feature, enabled, source)
buildExtensionErrorCount(date, code, count)
```

3. builder 只返回 allowlist 字段。
4. 增加 `assertAnalyticsPayloadIsSafe(payload)` 测试辅助函数。

### 验收

- 事件无法携带任意 payload。
- 测试确认 payload 不含 URL、hostname、title、referrer、text、selector。
- 数值设置已转成区间。

## 阶段 3：本地聚合点击计数

### 目标

统计上下按钮和高级跳转行为，但不记录页面上下文。

### 任务

1. 在用户点击顶部、底部、进度跳转、返回位置时增加本地计数。
2. Popup 和快捷键触发也计入对应聚合字段。
3. 计数按本地日期聚合。
4. content script 通过 `chrome.runtime.sendMessage` 发送安全事件名，不发送 URL。
5. background 在同意开启时才写入 `chrome.storage.local`。

建议计数字段：

```js
{
  topClicks,
  bottomClicks,
  progressJumpClicks,
  returnPositionClicks,
  popupTopClicks,
  popupBottomClicks,
  keyboardTopCommands,
  keyboardBottomCommands
}
```

### 验收

- 未开启统计时点击不写队列。
- 开启统计后只增加日级计数。
- 计数记录不包含站点信息。

## 阶段 4：设置快照和功能开关事件

### 目标

获得设置分布和高级功能启用率。

### 任务

1. 开启匿名统计后发送一次设置快照。
2. 保存设置后发送一次设置快照。
3. 功能开关变化时发送 `feature_toggle_change`。
4. 每天最多自动发送一次设置快照。

字段转换规则：

- `buttonSize` 转为 `small | medium | large | extraLarge`。
- `buttonSpacing` 转为 `compact | normal | loose`。
- `edgeDistance` 转为 `near | standard | far`。
- `opacity` 转为 `low | medium | high | solid`。
- 自定义颜色只记录 `customColorUsed: true/false`，不记录色值。

### 验收

- 可以计算页面进度条启用率。
- 可以计算按钮布局和尺寸偏好。
- 不上传精确颜色值或站点级禁用列表。

## 阶段 5：队列、重试和上传

### 目标

可靠上传聚合事件，并在失败时安全降级。

### 任务

1. 在 `background.js` 中实现队列：

```js
enqueueAnalyticsEvent(event)
flushAnalyticsQueue()
clearAnalyticsQueue()
```

2. 队列最多保留 200 条聚合事件。
3. 上传失败保留最多 7 天。
4. 使用 `fetch()` POST 到固定 HTTPS endpoint。
5. 不设置包含页面来源的 header。
6. 不从 content script 直接请求统计 endpoint。

### 验收

- endpoint 不可用时插件功能不受影响。
- 队列不会无限增长。
- 关闭统计会清空队列并停止重试。

## 阶段 6：Manifest 和权限

### 目标

只增加最小必要网络权限。

### 任务

1. 在 `manifest.json` 中新增固定统计域名权限。
2. 不新增 `<all_urls>` 网络请求权限。
3. 检查 CSP 仍不允许远程脚本。
4. 如果统计域名未确定，不合并运行时代码，只保留规划。

### 验收

- 权限解释能通过商店审核。
- 统计端点权限范围最小。

## 阶段 7：隐私政策和商店资料

### 目标

确保实际行为与披露完全一致。

### 任务

1. 更新 `doc/privacy-policy.md`。
2. 更新 `doc/privacy-policy-zh.md`。
3. 更新 `doc/CHROME_WEB_STORE_LISTING_CONTENT.md` 的隐私说明。
4. 更新 `doc/PUBLISH_CHECKLIST.md` 发布前检查项。
5. Chrome Web Store 后台选择对应数据使用披露。

隐私政策必须说明：

- 统计默认关闭。
- 用户主动开启后才发送。
- 收集功能开关、设置选项、聚合点击次数。
- 不收集访问网址、页面标题、页面内容、个人信息。
- 如何关闭统计。
- 数据保留期和联系邮箱。

### 验收

- 文档不再声称“没有任何外部网络请求”，除非统计模块未上线。
- 商店后台披露与代码行为一致。

## 阶段 8：测试和审计

### 目标

用自动化测试防止后续误传敏感数据。

### 必测项

- 默认关闭时无统计队列、无网络请求。
- 开启后才创建队列。
- 关闭后清空队列。
- 所有 builder 输出字段符合 allowlist。
- payload 中不出现以下字段名或值：

```text
url
uri
origin
host
hostname
domain
title
referrer
text
html
selector
query
hash
pathname
```

- 点击计数按日聚合。
- 设置数值已转为区间。
- 上传失败不会影响滚动功能。

### 建议命令

```bash
node build.js
node tests/test-analytics-settings.js
node tests/test-analytics-payload-sanitization.js
node tests/test-analytics-queue.js
node tests/test-analytics-consent.js
git diff --check
```

## 阶段 9：发布前人工检查

### 检查清单

- Chrome Web Store 最新政策已复核。
- 隐私政策链接可访问。
- 设置页开关默认关闭。
- 打包产物中没有第三方远程统计 SDK。
- DevTools Network 验证默认状态无统计请求。
- 开启统计后请求体不含页面上下文。
- 关闭统计后刷新页面仍无统计请求。
- 商店资料没有继续写“无任何外部网络请求”。

## 完成定义

v2.1 只有在以下条件满足时才算完成：

- 用户不同意时，扩展行为与 v2.0 完全一致。
- 用户同意后，只发送规格允许的匿名聚合数据。
- 隐私政策和商店披露已更新。
- 自动化测试覆盖 consent、queue、payload sanitization。
- 已完成真实浏览器 Network 验证。
