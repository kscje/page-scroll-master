# v2.5.2 卸载调研产品规划

本文档定义 Page Scroll Master v2.5.2 的“卸载调研”规划范围。该功能目标是在用户卸载扩展后，打开一个轻量调研页面，让愿意反馈的用户选择卸载原因并补充说明，为后续默认值、兼容性、功能密度和文案改进提供依据。

## 版本定位

v2.5.2 仍应保持小版本收口，不引入新的页面滚动能力、账号体系、远程脚本或默认开启的数据采集。

从语义化版本看，卸载调研是新的用户反馈入口，严格说更接近 `Added` 类型能力。如果坚持放入 `2.5.2`，范围应控制为“反馈与调研基础设施补充”，不与滚动行为、设置页结构或新高级功能混合开发。

## 平台事实

Chrome 扩展卸载后，扩展页面、后台 Service Worker、storage 和内容脚本都不可再运行。因此该能力不能实现为“扩展内弹窗”。可行实现是：

- 在扩展仍安装时，由后台 Service Worker 调用 `chrome.runtime.setUninstallURL()` 注册卸载后打开的 HTTPS 页面。
- 用户卸载扩展后，Chrome 打开该 URL。
- 该 URL 指向开发者托管的网页，由用户自愿填写并提交卸载原因。

该 API 的 URL 必须是 `http:` 或 `https:`，最大长度 1023 字符；传空字符串表示不打开卸载页。v2.5.2 应使用 HTTPS 固定域名。

## 产品目标

1. 收集可操作的卸载原因，而不是泛泛收集“是否满意”。
2. 不读取或上传用户浏览历史、页面 URL、书签内容、站点启停列表、统计状态或本地设置明细。
3. 不在卸载时自动发送反馈正文；只有用户在调研页点击提交后才发送。
4. 复用现有反馈服务的隐私原则：内容不写入扩展 storage，服务端只保留无正文的投递/限流日志。
5. 给用户提供明确的跳过和关闭路径，不阻碍卸载。

## 非目标

- 不拦截、阻止、延迟或二次确认卸载。
- 不在卸载时自动上传设置快照、域名列表、页面 URL、浏览器语言或设备指纹。
- 不把卸载调研接入匿名使用统计 consent；两者是独立能力。
- 不新增第三方表单服务、广告分析、追踪像素、远程脚本或 Cookie。
- 不要求用户填写联系方式。
- 不在 v2.5.2 中实现复杂后台报表，只保证邮件投递和基础无内容日志可用。

## 调研页面体验

卸载后打开的页面应是一个独立 HTTPS 网页，建议标题：

```text
帮助我们改进 Smart Scroll Navigator
```

页面结构：

```text
你为什么卸载？

[ ] 不常使用
[ ] 按钮遮挡页面或干扰阅读
[ ] 滚动、进度条或书签功能不符合预期
[ ] 在某些网站上不兼容或不起作用
[ ] 设置太复杂
[ ] 性能、卡顿或页面异常
[ ] 隐私或权限顾虑
[ ] 找到了其他替代工具
[ ] 临时卸载，之后可能再安装
[ ] 其他

补充说明（可选）
联系方式（可选）

[提交反馈] [跳过]
```

交互规则：

- 卸载原因允许多选。
- 至少选择 1 个原因或填写 10 个字符以上补充说明，才允许提交。
- 补充说明上限 2000 字符。
- 联系方式上限 200 字符，禁止换行。
- 页面默认不请求图片，降低卸载后的提交成本。
- 提交成功后显示感谢和 Chrome Web Store / GitHub / 重新安装入口。
- 跳过按钮只关闭或显示“已跳过”状态，不发送任何反馈。
- 页面应适配移动宽度和桌面宽度，因为用户可能在不同 Chromium 浏览器中打开。

## 数据字段

提交 payload 建议：

```json
{
  "type": "uninstall",
  "reasons": ["too_complex", "site_incompatible"],
  "message": "Optional free text",
  "contact": "optional@example.com",
  "extensionVersion": "2.5.2",
  "language": "zh-CN",
  "source": "uninstall-survey",
  "schemaVersion": 1
}
```

字段边界：

- `extensionVersion` 来自注册卸载 URL 时拼入的版本参数。
- `language` 只使用扩展已知 UI 语言或默认语言；不读取调研页浏览器语言作为扩展行为证据。
- 不生成长期安装 ID。
- 不传 `chrome.storage.local` 或 `chrome.storage.sync` 中的任何用户数据。
- 不传当前页面 URL、历史访问域名、页面标题、页面内容或书签内容。

URL 参数建议保持短且非识别化：

```text
https://page-scroll-master-feedback.kscje-apps.workers.dev/uninstall?version=2.5.2&lang=zh-CN
```

不建议加入随机用户 ID、安装时间、域名状态、统计 consent 或设置摘要。

## 技术方案

### 扩展端

在 `background.js` 中新增卸载 URL 注册逻辑：

- 在 Service Worker 初始化时调用一次。
- 在 `chrome.runtime.onInstalled` 的 `install` 和 `update` 分支中再次调用，确保升级到 v2.5.2 后 URL 已刷新。
- 版本号从 `chrome.runtime.getManifest().version` 读取，避免硬编码。
- 语言使用现有 normalize 逻辑可接受的值；若后台无法可靠读取 `chrome.storage.sync.language`，则使用默认 `en-US` 或已有 storage 中的语言值。
- 对 URL 参数执行 `encodeURIComponent`。
- 捕获 `chrome.runtime.lastError` 或 Promise rejection，避免影响现有快捷键、统计和 onboarding 逻辑。

建议抽象：

```js
const UNINSTALL_SURVEY_BASE_URL = 'https://page-scroll-master-feedback.kscje-apps.workers.dev/uninstall';

async function registerUninstallSurveyUrl() {
  if (!chrome.runtime || typeof chrome.runtime.setUninstallURL !== 'function') return;
  const version = chrome.runtime.getManifest().version;
  const language = await readPreferredLanguageForSurvey();
  const url = `${UNINSTALL_SURVEY_BASE_URL}?version=${encodeURIComponent(version)}&lang=${encodeURIComponent(language)}`;
  await chrome.runtime.setUninstallURL(url);
}
```

不需要新增普通权限。调研页是卸载后由 Chrome 打开的网页，不是扩展页；提交请求由网页自身发起，不应要求扩展可选主机权限。

### 调研页面托管

首选复用现有 `feedback-backend` Worker 域名：

- `GET /uninstall` 返回静态 HTML、CSS 和少量内联 JS。
- `POST /v1/uninstall-feedback` 接收 JSON 调研提交。
- 或扩展现有 `POST /v1/feedback`，新增 `type=uninstall` 和 `source=uninstall-survey`。

建议优先新增独立路径 `POST /v1/uninstall-feedback`，好处是校验规则、字段长度和邮件标题更清晰，不影响现有扩展内图片反馈表单。

服务端规则：

- 只允许固定 reason 枚举。
- 每次提交最多 10 个原因。
- message 上限 2000 字符。
- contact 上限 200 字符且禁止换行。
- version 必须符合扩展版本格式。
- language 必须属于当前支持语言集合，未知值回退为 `en-US` 或记录为 `unknown`。
- 使用现有 IP hash 小时级限流。
- D1 只保存 request id、reason 枚举、reason 数量、是否有 message、是否有 contact、投递状态和过期时间。
- 不保存 message、contact 或明文 IP。
- 通过 Resend 转发完整内容到开发者邮箱。

### 隐私与商店材料

v2.5.2 实现前必须更新：

- `chrome-web-store/privacy/*.md`
- `README.md`
- `doc/CHANGELOG.md`
- `options.js` 设置页更新记录
- `chrome-web-store/publish-checklist.md`
- 必要时 `chrome-web-store/publish-guide.md`

隐私文案必须明确：

- 卸载后可能打开一个自愿调研网页。
- 页面打开本身不提交卸载原因。
- 只有用户点击提交后才发送所选原因、补充说明、可选联系方式、扩展版本和界面语言。
- 不发送访问网址、页面内容、书签内容、站点状态或设置明细。
- 服务端不保存正文和联系方式，仅保存无正文投递日志与限流信息。

如 Chrome Web Store 后台 Data usage 需要披露“用户支持/反馈”用途，应同步更新，不能只改仓库文档。

## 本地化范围

调研页面首版至少支持现有 13 种界面语言：

- `zh-CN`
- `zh-TW`
- `en-US`
- `es-ES`
- `ja-JP`
- `de-DE`
- `fr-FR`
- `pt-BR`
- `ko-KR`
- `it-IT`
- `ru-RU`
- `tr-TR`
- `id-ID`

实现上可以在 Worker 静态页面中内置小型翻译表。首版不新增 `_locales` 目录，因为调研页不是扩展原生界面；但卸载 URL 的 `lang` 参数必须与扩展现有语言归一化规则一致。

## 实施拆分

### 阶段 1：确认隐私边界和页面域名

1. 确认是否复用 `page-scroll-master-feedback.kscje-apps.workers.dev`。
2. 确认调研页是否需要后续切换到自定义域名。
3. 确认提交字段只包含 reason、message、contact、version、language、source 和 schemaVersion。
4. 确认不采集设置快照、域名、安装 ID、页面 URL 或统计 consent。

### 阶段 2：后端和调研页

1. 在 `feedback-backend/worker.js` 增加 `GET /uninstall`。
2. 增加 `POST /v1/uninstall-feedback` 校验、限流、日志和邮件转发。
3. 更新 `feedback-backend/schema.sql`，如需新表或字段，保持无正文日志。
4. 增加 Worker 单元测试或可运行的本地校验脚本。
5. 验证 CORS、Content-Type、错误状态和限流行为。

### 阶段 3：扩展端注册

1. 在 `background.js` 增加卸载 URL 注册 helper。
2. 在初始化、安装和更新路径调用 helper。
3. 保证 helper 失败不影响快捷键、onboarding 和匿名统计。
4. 增加后台测试，覆盖 URL 参数、版本读取、语言回退和 API 不存在时的安全退出。

### 阶段 4：文档、版本和发布材料

1. 将 `manifest.json`、README、CHANGELOG 和设置页更新记录同步到 `2.5.2`。
2. 更新隐私政策的所有语言版本。
3. 更新商店发布清单和必要的 Data usage 检查项。
4. 只在用户明确要求生成发布包时运行 `node build.js`。

## 验收标准

- 升级到 v2.5.2 后，后台成功注册 HTTPS 卸载调研 URL。
- 注册 URL 长度低于 1023 字符。
- 未安装或浏览器不支持 `setUninstallURL` 时，不影响扩展其他功能。
- 用户卸载后 Chrome 打开调研页；关闭或跳过不会发送反馈。
- 用户提交后，服务端校验 reason、message、contact、version 和 language。
- 服务端邮件包含卸载原因和补充说明，D1 不保存正文、联系方式或明文 IP。
- 调研页不包含第三方远程脚本、追踪像素、Cookie 或广告分析。
- 隐私政策和商店 Data usage 与实际数据处理一致。
- 现有扩展内反馈表单继续可用，不因新增卸载调研改变图片反馈校验。

## 验证建议

按改动范围运行最小充分验证：

```bash
node tests/test-feedback-client.js
node tests/test-options-page.js
node tests/test-language-normalization.js
git diff --check
```

如果新增后台专项测试，建议命名为：

```bash
node tests/test-uninstall-survey.js
```

如果修改 Worker，需补充对应 Worker 校验命令或脚本，并至少覆盖：

- 有效提交。
- 未选择原因且说明过短。
- 未知 reason。
- message 过长。
- contact 换行。
- version 非法。
- language 未知。
- 限流。

发布包验证仍遵循项目规则：只有用户明确要求准备发布 ZIP 或检查发布产物时，才运行 `node build.js`。

## 风险与取舍

- 卸载后打开新页面可能被部分用户视为打扰，因此页面必须轻、可跳过，并且不应打开多个页面。
- `workers.dev` 在部分网络中可能不可达；如果后续反馈价值明显，应考虑自定义域名。
- 卸载用户的反馈样本会天然偏向愿意填写的人，不能直接代表全部卸载原因。
- 该功能提供的是定性反馈，不应替代可选匿名统计中的聚合使用趋势。
- 如果隐私政策或商店 Data usage 未同步，发布风险高于实现风险，应作为发布阻断项。

## 完成定义

v2.5.2 只有在以下条件满足时才算完成：

- 产品边界确认：无自动卸载数据上传，无设置/域名/页面内容采集。
- 卸载 URL 注册、调研页、提交端点和服务端转发均已实现。
- 隐私政策、README、CHANGELOG、设置页更新记录和发布清单均已同步。
- 相关 Node/Worker 回归与 `git diff --check` 通过。
- 如需真实 Chrome 验收，已通过手动卸载测试确认页面打开和提交链路可用。
- 未在未获明确要求时生成或提交 `dist/` 发布产物。
