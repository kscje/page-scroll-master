# v1.8 Advanced Controls 实施计划

本文档用于指导 Codex 后续按步骤实现 v1.8。执行开发时应优先保证每个阶段可测试、可回退、不会改变默认体验。

## 开发总原则

- 先抽取共用逻辑，再新增 UI。
- 每一步完成后运行相关测试。
- 高级功能默认关闭，关闭时不应创建额外 DOM 或监听。
- 先实现横向进度条，再实现纵向进度按钮。
- 先实现内部 SVG 图标选择，不实现用户上传。
- 站点管理复用现有 `enableStates`，不要引入新的站点状态 key。

## 阶段 1：抽取通用平滑滚动

### 目标

为进度条点击跳转准备统一滚动接口，同时保证现有顶部/底部滚动行为不变。

### 任务

1. 在 `content.js` 新增：

```js
function smoothScrollTo(container, targetTop) {}
```

2. 修改 `scrollToTop()`：

```js
function scrollToTop() {
  const container = resolveScrollContainer();
  smoothScrollTo(container, 0);
}
```

3. 修改 `scrollToBottom()`：

```js
function scrollToBottom() {
  const container = resolveScrollContainer();
  smoothScrollTo(container, getElementScrollRange(container));
}
```

4. 确保 `scrollSpeed` 仍控制动画时间。

### 验收

- 点击顶部按钮行为不变。
- 点击底部按钮行为不变。
- 快捷键行为不变。

### 建议测试

扩展现有滚动测试：

- `smoothScrollTo()` target 小于 0 时 clamp 到 0。
- target 大于 range 时 clamp 到 range。
- `scrollToTop()` 调用目标为 0。
- `scrollToBottom()` 调用目标为 range。

## 阶段 3：实现横向进度条

### 目标

先实现风险较低的顶部/底部横向进度条。

### 任务

1. 在 `content.js` 新增：

```js
function createHorizontalProgressBar(rootOrHost) {}
function updateHorizontalProgressBar(progress) {}
function removeHorizontalProgressBar() {}
```

2. 可选择复用现有 Shadow DOM host，或创建独立 host：

推荐复用同一个 `HOST_ID` 的 Shadow Root，避免多 host 管理复杂。

3. 横向条结构建议：

```html
<div class="psm-horizontal-progress">
  <div class="psm-horizontal-progress-fill"></div>
  <span class="psm-horizontal-progress-label"></span>
</div>
```

4. 样式：

- `position: fixed`
- `left: 0`
- `right: 0`
- top 或 bottom 由设置决定
- height 为 `thickness`
- z-index 稍低于按钮组
- label 仅在 `showPercentage` 开启时显示

5. 点击处理：

```js
ratio = (event.clientX - rect.left) / rect.width;
smoothScrollTo(container, range * ratio);
```

6. `clickToJump = false` 时设置 `cursor: default`，不响应点击。

### 验收

- 顶部位置显示正确。
- 底部位置显示正确。
- 颜色和粗细设置生效。
- 点击左侧跳顶部，点击右侧跳底部。
- 全屏隐藏。
- 站点禁用移除。

### 建议测试

`test-progress-bar.js`：

- 横向点击比例计算正确。
- `clickToJump = false` 不调用滚动。
- `showPercentage` 开启时 label 文案正确。

## 阶段 4：实现纵向进度按钮

### 目标

在现有按钮组中加入第三个“进度按钮”，并复用按钮样式体系。

### 任务

1. 修改 `createScrollButton()`，在 top 和 bottom 之间按设置插入 progress button。
2. 注意默认关闭时不插入该按钮。
3. 结构建议：

```html
<button class="psm-scroll-button psm-progress-button" type="button">
  <span class="psm-progress-fill"></span>
  <span class="psm-progress-label"></span>
</button>
```

4. 样式：

- 宽度与按钮一致
- 高度为 `verticalHeight`
- border radius 跟随 shape
- background 可用透明或深浅背景
- fill 从底部向上增长
- label 层置顶

5. 更新 `updateButtonStyle()`：

- 对 progress button 应用宽度、高度、形状、透明度、颜色。
- `buttonContainer.style.gap` 继续使用 `buttonSpacing`。

6. 点击处理：

```js
ratio = 1 - ((event.clientY - rect.top) / rect.height);
smoothScrollTo(container, range * ratio);
```

7. 修改 `getButtonElements()`，返回 progressButton。

### 验收

- 开启纵向模式后显示三按钮。
- 关闭后恢复两按钮。
- 修改按钮尺寸后进度按钮宽度跟随。
- 修改按钮形状后进度按钮圆角跟随。
- 修改按钮间距后上/进度/下之间间距跟随。
- 点击顶部附近跳到底部附近。
- 点击底部附近跳到顶部附近。

### 建议测试

`test-progress-bar.js`：

- 纵向点击比例计算正确。
- 纵向模式 DOM 创建和移除正确。

## 风险清单

### 进度条与 SPA 容器

风险：Notion、飞书、语雀等页面可能动态替换滚动容器。

处理：

- 容器变化时重新绑定滚动监听。
- 不缓存旧容器。
- 每次点击跳转前重新 `resolveScrollContainer()`。

### 横向进度条遮挡网页

风险：顶部/底部 fixed 条可能覆盖网页内容。

处理：

- 默认粗细 3px。
- 不添加 body padding。
- 允许用户关闭或选择纵向模式。

### 纵向进度按钮与按钮尺寸

风险：用户设置极小按钮尺寸时进度按钮可读性差。

处理：

- 纵向高度独立设置。
- 最小高度 40px。
- 百分比默认关闭。

### 无限滚动页面

风险：`scrollHeight` 动态增长导致进度回退。

处理：

- v1.8 不承诺完美适配无限滚动。
- 设置页加入注意事项。
- 后续版本可增加站点级默认关闭策略。

### 语言翻译不完整

风险：自定义 translations 与 `_locales` 不一致。

处理：

- 新文案添加时同步更新四套语言。
- 测试检查关键 key 存在。

## 最小可交付切片

如果开发时间有限，v1.8 可按以下最小切片交付：

1. `advancedSettings` 默认值和保存。
2. 通用 `smoothScrollTo()`。
3. 横向进度条。
4. 纵向进度按钮。
5. 图标自定义。
6. 网站管理。
7. 新语言。

若必须进一步裁剪，优先保留：

- 横向进度条
- 纵向进度按钮
- 图标颜色和图标组

可延后：

- 剩余阅读时间
- 网站管理批量操作
- 图标预览的精细 UI
