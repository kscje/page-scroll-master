# v1.9 Reading & Language 实施计划

本文档用于指导 Codex 后续按步骤实现 v1.9。执行前应确认 v1.8 已完成，尤其是 `advancedSettings`、多语言基础结构、设置页高级功能区域和 `smoothScrollTo()` 已存在。

## 开发总原则

- 先补设置结构，再接页面 UI。
- 滚动位置书签默认关闭。
- 建议&反馈提交模块不纳入 v1.9，延后到 v2.2。
- 新增语言要覆盖 Options、Popup 和 Chrome locale 文件。
- 每个阶段完成后运行相关测试。

## 阶段 0：扩展 advancedSettings

### 目标

在不改变默认体验的前提下，为滚动位置书签加入设置结构。

### 任务

1. 在默认设置中新增：

```js
readingPosition: {
  enabled: false,
  saveMode: 'beforeJump',
  restoreMode: 'prompt',
  retentionDays: 30
}
```

2. 确保 `mergeAdvancedSettings()` 能合并该对象。
3. 确保旧用户无该字段时自动补齐。

### 验收

- 默认 `readingPosition.enabled = false`。
- 默认页面无恢复提示、无返回点。
- v1.8 的高级功能不受影响。

## 阶段 1：实现阅读位置存储工具

### 目标

提供读写 `chrome.storage.local.readingPositions` 的工具函数。

### 任务

在 `content.js` 或合适位置新增：

```js
function getNormalizedPageKey()
function getCurrentReadingPosition()
function saveReadingPosition(reason)
function loadReadingPosition(callback)
function cleanupExpiredReadingPositions()
```

建议存储：

```js
readingPositions: {
  '<normalized-url>': {
    top,
    range,
    progress,
    updatedAt,
    hostname
  }
}
```

URL 归一化：

- `location.origin + location.pathname`
- 不含 hash
- 不含 query

### 验收

- 可保存当前位置。
- 可读取当前位置。
- 可清理过期记录。
- 不使用 `chrome.storage.sync`。

### 建议测试

`test-reading-position.js`：

- URL 归一化正确。
- 过期记录被删除。
- range 为 0 时不保存或保存安全值。

## 阶段 2：接入跳转前记录与返回点

### 目标

用户点击顶部/底部/进度条跳转前记录当前位置，跳转后显示返回点。

### 任务

1. 在 `scrollToTop()`、`scrollToBottom()` 和进度条点击跳转前调用：

```js
recordPositionBeforeProgrammaticJump()
```

2. 新增返回点 DOM：

```html
<button class="psm-return-position-button" type="button"></button>
```

3. 返回点跟随按钮组位置。
4. 点击返回点调用 `smoothScrollTo(container, savedTop)`。
5. 全屏、站点禁用、按钮移除时同步隐藏或移除。

### 验收

- 点击顶部前记录位置。
- 跳到顶部后显示返回点。
- 点击返回点回到原位置。
- 再次跳转可更新返回点目标。

## 阶段 3：实现恢复提示

### 目标

页面打开时可提示用户恢复到上次阅读位置。

### 任务

1. 内容脚本初始化后读取当前页面 `readingPositions`。
2. 判断是否应该提示：

- `readingPosition.enabled = true`
- `restoreMode = 'prompt'`
- 存在记录
- 记录未过期
- 记录 top 不接近 0
- 当前页面可滚动

3. 创建轻提示：

```text
恢复到上次阅读位置？ [恢复] [忽略]
```

4. 点击恢复后调用 `smoothScrollTo()`。
5. 点击忽略后本次页面生命周期不再提示。

### 验收

- 有记录时显示提示。
- 点击恢复能滚动。
- 点击忽略后不重复提示。
- 关闭功能时不提示。

## 阶段 4：实现自动保存模式

### 目标

支持 `saveMode = 'auto'`。

### 任务

1. 滚动时防抖保存，建议 1000ms。
2. `visibilitychange` 页面隐藏时保存一次。
3. `beforeunload` 时尽力保存一次。
4. 不要每次滚动都写 storage。

### 验收

- 自动模式能保存位置。
- 高频滚动不会频繁写 storage。
- 关闭功能后解绑监听。

## 阶段 5：设置页接入滚动位置书签

### 目标

用户可配置滚动位置书签。

### 任务

在 `options.html` 新增：

```text
[ ] 启用滚动位置书签
保存方式：跳转前记录 / 自动记录
恢复方式：显示提示 / 自动恢复 / 仅手动
保留记录：[30] 天
```

在 `options.js`：

- 加载设置
- 保存设置
- 验证 `retentionDays` 范围，建议 1-365
- 增加清理历史记录按钮可选

### 验收

- 设置保存后内容脚本响应。
- 默认关闭。
- 保留天数校验生效。

## 风险清单

### 反馈提交服务范围膨胀

风险：直接提交反馈、图片上传和邮箱转发需要服务端、远程请求权限、限流、反垃圾和隐私披露，容易拖慢 v1.9 主线。

处理：

- v1.9 明确不做建议&反馈提交模块。
- v2.2 再实现 Cloudflare Worker + 邮件服务的反馈提交方案。

### 多语言文案遗漏

风险：新增语言多，容易漏 key。

处理：

- 测试检查各语言 key 完整性。
- 未命中 key 时回退英文。

### 自动保存写入过于频繁

风险：滚动位置书签自动模式写 storage 太频繁。

处理：

- 防抖 1000ms。
- 页面隐藏时保存。
- beforeunload 尽力保存。

v1.9 只有在以下条件满足时才算完成：

- 滚动位置书签默认关闭。
- 开启后可记录跳转前位置并返回。
- 可显示恢复提示。

- 所有现有测试通过。
