# 产品需求池与待评估功能

本文档记录 Page Scroll Master 暂缓推进、需要后续重新评估的产品需求。进入本需求池的功能不属于当前版本承诺范围，不能在 README、CHANGELOG、商店文案或发布清单中宣称已实现。

## 管理规则

- 每个需求必须标明状态、暂缓原因、重新评估条件和可能涉及的风险。
- 从需求池移入版本规划前，必须先更新对应版本的产品规划文档。
- 涉及新增权限、远程服务、遥测、页面内容采集或隐私披露变化的需求，必须先单独确认边界。
- 涉及 UI 密度、布局、按钮数量或设置项复杂度的需求，必须同时评估 Options 预览和真实页面运行时。
- 涉及新增语言的需求，必须先查看 Chrome Web Store 后台地区分布、评论语言、反馈邮件语言和安装来源，而不是只按通用语言排名推进。

## 状态定义

- `待评估`：已有初步方向，但缺少足够数据或产品判断。
- `暂缓`：已讨论过，但当前版本明确不推进。
- `可进入规划`：前置评估已完成，可放入后续版本规划。
- `拒绝`：明确不适合本插件定位或成本高于收益。

## 候选需求一：简洁/完整按钮模式

状态：`暂缓`

来源：v2.5 规划讨论中提出，后续从 v2.5 必做范围移出。

### 暂缓原因

当前插件已经有多个独立按钮和高级功能入口。简洁/完整按钮模式可以缓解按钮拥挤，但会引入新的菜单层级、状态同步、Options 预览分支、无障碍行为和真实页面布局复杂度。该需求需要在明确按钮拥挤已经成为真实用户痛点后再推进。

### 重新评估条件

- 用户反馈中多次出现“按钮太多”“遮挡页面”“不知道哪个按钮是什么”的问题。
- 匿名统计或本地调研显示多个高级功能同时启用的比例较高。
- Options 预览和真实页面按钮顺序已有稳定抽象，新增收纳菜单不会显著扩大维护成本。
- 性能体检确认当前高级功能关闭状态和启停清理已经可靠。

### 产品目标

当页面进度条、按屏跳转、滚动位置书签、智能段落跳转和自动滚屏同时开启时，页面边缘按钮会变多。候选方案是提供“简洁模式 / 完整模式”，让用户可以在低干扰和完整控制之间切换。

该能力解决的是“常驻按钮数量”问题，不改变任何功能本身是否启用。用户在 Popup 中开启的高级功能仍然可用，只是在简洁模式下把部分低频入口收纳起来。

### 模式定义

新增按钮显示模式：

```js
buttonSettings: {
  buttonDisplayMode: 'full' | 'compact'
}
```

默认值为 `full`，避免旧用户升级后发现已启用的独立按钮突然消失。

字段归属：

- `buttonDisplayMode` 属于全局按钮外观设置，建议放入 `chrome.storage.sync` 的 `buttonSettings`。
- 不按主域名保存；同一用户在不同网站看到一致的按钮密度偏好。
- 旧用户缺少该字段时，通过深合并补齐为 `full`。
- 存储异常或未知值回退为 `full`。

```text
完整模式
  显示当前主域名已启用的所有功能按钮。

简洁模式
  保留回到顶部、回到底部、必要进度展示和一个“更多”入口。
  其他可操作高级功能进入“更多”菜单。
```

### 设置页入口

设置页在基础按钮设置区域新增“按钮显示模式”选项，位置建议放在“按钮间距”或“透明度”附近，因为它控制的是按钮组密度，而不是某个高级功能细节：

```text
按钮显示模式
(•) 完整模式：显示所有已启用功能按钮
( ) 简洁模式：保留主要按钮，其他功能收纳到“更多”
```

规则：

- 切换后立即更新设置页预览。
- 保存后通知已打开页面刷新按钮布局。
- 该选项不出现在 Popup 中，避免 Popup 的站点启停语义和全局外观设置混在一起。
- 文案应明确“简洁模式不会关闭功能”，防止用户误以为高级功能被禁用。

### 完整模式规则

完整模式沿用 v2.4 之前的按钮展示逻辑。当前主域名启用多少功能，就显示对应独立按钮。

主按钮组顺序保持：

```text
回到顶部
上一屏（启用按屏跳转时）
纵向页面进度按钮（启用页面进度条且模式为纵向按钮时）
下一屏（启用按屏跳转时）
回到底部
页面中部滚动位置书签（启用且配置为页面中部时）
页面中部智能段落跳转（启用且配置为页面中部时）
页面中部自动滚屏（启用且配置为页面中部时）
```

页面顶部和页面底部区域继续按各功能自己的 `buttonPosition` 显示独立按钮。完整模式不新增“更多”入口。

### 简洁模式总体规则

简洁模式不应隐藏功能本身，只减少常驻按钮数量：

- 顶部、底部主按钮始终保留。
- 纵向页面进度按钮默认保留在主按钮组内，因为它同时承担页面进度展示。
- 横向页面进度条仍按顶部或底部横条显示，不进入“更多”菜单。
- 上一屏、下一屏、滚动位置书签、智能段落跳转和自动滚屏进入“更多”菜单。
- “更多”入口只在至少一个可收纳功能在当前主域名启用时显示。
- “更多”入口加入主按钮组，放在回到底部按钮之后。
- 简洁模式不读取或覆盖各高级功能的按钮位置配置；这些配置只在完整模式下决定独立按钮位置。

简洁模式主按钮组建议顺序：

```text
回到顶部
纵向页面进度按钮（启用页面进度条且模式为纵向按钮时）
回到底部
更多（存在可收纳功能时）
```

如果页面进度条为横向顶部或横向底部模式：

```text
回到顶部
回到底部
更多（存在可收纳功能时）
横向页面进度条（按原设置显示在页面顶部或底部）
```

### 可收纳功能范围

简洁模式首版收纳以下功能：

| 功能 | 完整模式 | 简洁模式 |
| --- | --- | --- |
| 回到顶部 | 独立按钮 | 保留独立按钮 |
| 回到底部 | 独立按钮 | 保留独立按钮 |
| 页面进度条：纵向按钮 | 独立进度按钮 | 保留独立进度按钮 |
| 页面进度条：横向条 | 横向顶部/底部条 | 保留横向条 |
| 上一屏 | 独立按钮 | 收纳到“更多” |
| 下一屏 | 独立按钮 | 收纳到“更多” |
| 滚动位置书签 | 独立按钮和菜单 | 收纳到“更多” |
| 智能段落跳转 | 独立按钮和菜单 | 收纳到“更多” |
| 自动滚屏 | 独立播放按钮 | 收纳到“更多” |

不纳入首版收纳：

- 全屏自动隐藏，因为它是可见性规则，不是功能入口。
- 鼠标悬停 + 快捷键隐藏，因为它仍作用于整个按钮容器和“更多”菜单。
- Chrome 全局快捷键，因为它不依赖页面按钮显示。

### “更多”入口

“更多”入口是一个常驻按钮，只有在简洁模式且至少一个可收纳功能启用时创建：

```text
...
```

入口规则：

- 使用现有按钮尺寸、形状、间距、透明度和同侧位置。
- 背景色默认跟随顶部按钮颜色。
- 图标使用 `currentColor`，不跟随用户选择的顶部/底部箭头图标样式。
- `title` 和 `aria-label` 使用“更多滚动工具”。
- `aria-expanded` 反映菜单开关状态。
- 点击外部、按 `Escape`、页面卸载、SPA 路由变化或当前主域名关闭插件时关闭菜单。

### “更多”菜单内容

点击“更多”后显示轻量菜单。菜单只展示当前主域名已经启用、且在简洁模式被收纳的功能：

```text
更多滚动工具
  上一屏
  下一屏
  保存/恢复滚动位置
  智能段落跳转
  开始自动滚屏 / 暂停自动滚屏
```

菜单项规则：

- 按固定顺序展示：上一屏、下一屏、滚动位置书签、智能段落跳转、自动滚屏。
- 未启用的功能不显示，而不是显示禁用项。
- 上一屏在顶部时可禁用；下一屏在底部时可禁用。
- 自动滚屏菜单项根据当前状态显示“开始自动滚屏”“暂停自动滚屏”或“继续自动滚屏”。
- 滚动位置书签和智能段落跳转可以复用现有菜单内容，但外层入口必须来自“更多”菜单，避免同时出现独立按钮和收纳入口。
- 菜单打开时如果用户执行跳转、保存、恢复、开始播放或关闭插件，应按现有功能规则关闭或刷新菜单。

### 菜单定位

“更多”菜单应贴近“更多”按钮，并遵守现有侧边位置：

- 按钮在右侧时，菜单向左展开。
- 按钮在左侧时，菜单向右展开。
- 靠近页面顶部或底部时，菜单应自动避让视口边缘。
- 菜单最大高度不超过视口高度的 60%，内容过多时内部滚动。
- 菜单层级应高于扩展自身按钮，但不使用过高 `z-index` 去压过浏览器或网站关键浮层。

### 与现有设置的关系

- 简洁模式不修改各高级功能的启用状态。
- 简洁模式不删除各功能的颜色、位置、速度、书签数量、目录来源或自动滚屏暂停规则。
- 切回完整模式后，各功能按原有设置恢复独立按钮显示。
- 主域名插件总开关关闭时，不创建主按钮、高级功能按钮或“更多”入口。
- Options 预览和真实页面应使用同一按钮排序规则。
- 站点某个高级功能关闭后，“更多”菜单立即移除对应菜单项。
- “更多”菜单不改变 Popup 中各高级功能开关状态。
- 页面中部、页面顶部、页面底部这些独立按钮位置配置在简洁模式下暂时不生效，但配置值仍保留。

### 自动滚屏状态规则

自动滚屏被收纳后仍应保持明确状态：

- 未播放时，菜单项显示“开始自动滚屏”。
- 播放中时，菜单项显示“暂停自动滚屏”，并可在“更多”按钮上显示轻量播放状态，例如 `aria-pressed="true"` 或小型状态点。
- 暂停时，菜单项显示“继续自动滚屏”。
- 到达页面底部、站点关闭、SPA 路由变化或滚动容器失效后，状态回到停止。
- 简洁模式不能因为菜单关闭而让自动滚屏失去停止或暂停入口；再次打开“更多”必须能看到当前状态。

### 无障碍与键盘行为

- “更多”按钮必须可键盘聚焦。
- `Enter` / `Space` 打开或关闭菜单。
- `Escape` 关闭菜单并把焦点返回“更多”按钮。
- 菜单打开后，`Tab` 可在菜单项中移动；不强制实现复杂焦点陷阱，但不能让焦点丢失到不可见元素。
- 每个菜单项使用 `button`，不要使用不可聚焦的 `div` 模拟。
- 菜单项应有本地化文本，不只依赖图标。

### 性能与清理

- 完整模式下不创建“更多”入口和菜单 DOM。
- 简洁模式下如果没有可收纳功能启用，不创建“更多”入口和菜单 DOM。
- 菜单关闭时可保留轻量容器，但不得保留昂贵目录快照或持续监听。
- 智能段落跳转只有在用户打开相关菜单项时才解析或刷新目录，不因“更多”菜单存在而提前扫描标题。
- 自动滚屏没有播放时，不应因被收纳而启动动画帧。
- 切换显示模式、storage 更新、站点启停、SPA 路由变化和页面卸载时，应复用现有清理路径。

### 本地化范围

按钮显示模式属于 Options 内嵌文案，必须覆盖：

- `options.html` 中新增控件和说明文案。
- `options.js` 的 Options 翻译表。

“更多”入口和菜单属于内容脚本文案，必须覆盖：

- `_locales/*/messages.json` 中的内容脚本文案 key。
- 必要时 `options.js` 的预览文案。

建议新增文案 key：

```text
buttonDisplayModeLabel
buttonDisplayModeFull
buttonDisplayModeCompact
buttonDisplayModeCompactHint
moreTools
moreToolsPreviousScreen
moreToolsNextScreen
moreToolsBookmarks
moreToolsOutline
moreToolsAutoScrollStart
moreToolsAutoScrollPause
moreToolsAutoScrollResume
```

### 验收标准

- 旧用户升级后默认仍为完整模式，已启用的独立按钮不消失。
- 设置页切换简洁/完整模式后，预览立即更新。
- 完整模式不创建“更多”按钮，按钮顺序与 v2.4 保持一致。
- 简洁模式下只保留顶部、底部、必要进度展示和“更多”入口。
- 简洁模式下未启用任何可收纳功能时，不显示“更多”入口。
- “更多”菜单只展示当前主域名已启用的可收纳功能。
- 通过“更多”菜单触发上一屏、下一屏、书签、目录和自动滚屏时，行为与完整模式独立按钮一致。
- 切回完整模式后，各功能按照原来的按钮位置和颜色设置恢复独立按钮。
- 主域名插件总开关关闭时，不创建“更多”入口或菜单。
- Options 预览和真实页面在按钮数量、顺序、间距和收纳规则上保持一致。
- 键盘操作和 `Escape` 关闭行为可用。
- 反复切换简洁/完整模式 10 次，不产生重复 DOM、重复监听器或残留菜单。

## 候选需求二：新增语种支持

状态：`待评估`

来源：v2.5 规划讨论中提出，后续从 v2.5 必做范围移出。

### 暂缓原因

当前已支持 13 种界面语言，已覆盖较大比例的潜在 Chrome 用户。继续新增语言的边际收益下降，但会增加 Options、Popup、内容脚本、Chrome locale、商店文案、发布资料和视觉回归成本。新增语言应优先由真实用户分布数据驱动，而不是按通用语言榜单自动推进。

### 重新评估条件

- Chrome Web Store 后台显示某些未支持语言地区有明显安装或曝光。
- 用户评论、反馈邮件或商店问题集中来自某个未支持语言。
- 有足够时间做翻译校对和 Popup 窄宽度视觉检查。
- 语言为从左到右布局，或已经为 RTL 语言单独规划布局改造。

### 候选语言池

低布局风险候选：

- 荷兰语：`nl-NL`，Chrome locale 目录 `_locales/nl/`
- 波兰语：`pl-PL`，Chrome locale 目录 `_locales/pl/`
- 越南语：`vi-VN`，Chrome locale 目录 `_locales/vi/`

可替换候选：

- 泰语、乌克兰语、捷克语、罗马尼亚语等，应根据商店后台和反馈来源决定。

暂不建议直接纳入：

- 阿拉伯语、希伯来语等 RTL 语言。它们不只是翻译问题，还涉及方向、对齐、图标位置、边距、表格和 Popup 窄宽度布局。

### 必须同步的位置

如果后续进入版本规划，必须同步：

- `options.js` 的 Options 翻译表和 `normalizeLanguage()`。
- `popup.js` 的 Popup 翻译表和 `normalizeLanguage()`。
- `options.html` 的语言选择器。
- `_locales/<locale>/messages.json`。
- Manifest、命令说明、内容脚本及 Chrome 原生界面的 locale key。
- 设置页快速开始、更新记录、匿名统计、反馈、评分入口和当前版本新增功能文案。
- README、商店文案和发布检查清单中的语言数量与列表。

### 自动检测示例

如果采用荷兰语、波兰语、越南语：

```text
nl-* -> nl-NL
pl-* -> pl-PL
vi-* -> vi-VN
```

规则：

- 未识别语言继续回退 `en-US`。
- 保存的显式语言优先于浏览器自动检测。
- Options、Popup 和内容脚本必须返回一致的规范语言代码。
- locale key 集合必须与 `_locales/en/messages.json` 完全对齐。

### 本地化质量要求

- 语言名称在选择器中使用本地写法，例如 `Nederlands`、`Polski`、`Tiếng Việt`。
- 不直接提交未经检查的机器翻译。
- 检查长词和带声调文本在 Popup 窄宽度下的换行。
- 检查设置页折叠标题、恢复默认确认弹窗、反馈表单和评分入口文案长度。
- 新增语言必须通过 `node tests/test-language-normalization.js`。

### 验收标准

- 新增语言都能通过设置页手动选择。
- 浏览器语言自动检测正确。
- Options、Popup、内容脚本、Manifest 和命令说明没有缺失文案。
- 切换语言后新增功能文案同步更新。
- Popup 窄窗口、设置页卡片和域名状态表没有截断关键操作。
- Chrome locale key 集合与英文基准完全对齐。
