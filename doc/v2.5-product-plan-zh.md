# v2.5 Usability, Compatibility & Performance 产品规划

本文档定义 Page Scroll Master v2.5 的整体产品范围。v2.5 不继续堆叠新的重型阅读功能，而是在 v2.4 现有能力之上，聚焦设置页减负、文档类 SPA 兼容性、未启用功能零开销检查和滚动卡顿优化。

当前 worktree 的首个开发批次先推进“性能体检 + 卡顿优化”。设置页减负、恢复默认和更大范围的站点兼容性增强保留在 v2.5 总规划内，但不与本批次混合开发，避免 UI 改动、可见行为变化和底层质量改进互相干扰。

## 版本目标

v2.5 聚焦四项能力：

1. 设置页减负：高级功能分组折叠，并提供恢复默认能力。
2. 兼容性增强：继续打磨 Notion、飞书、语雀、钉钉文档等文档类 SPA 和自定义滚动容器。
3. 性能体检：确认未启用功能不创建额外监听器、MutationObserver、定时器或动画帧。
4. 卡顿优化：优化部分页面回到顶部、回到底部和平滑滚动时的小卡顿。

该版本的核心目标是让插件在功能已经较完整的情况下变得更轻、更稳、更容易理解，而不是把 Page Scroll Master 扩展成复杂的阅读平台。

## 非目标

- 不新增 AI 总结、翻译、朗读、沉浸阅读或全文清理模式。
- 不新增远程服务、账号体系、云同步或新的默认开启数据采集。
- 不新增需要长期常驻扫描页面正文的功能。
- “简洁模式 / 完整模式”暂缓推进，移入产品需求池，v2.5 不实现按钮收纳或“更多”菜单。
- 新增语种支持暂缓推进，移入产品需求池，v2.5 不新增 locale。
- 不尝试绕过 Chrome 扩展命令、内容脚本和跨域 iframe 的平台限制。
- 首个开发批次不修改设置页信息架构、恢复默认 UI 或商店资料，只处理性能体检与卡顿优化所需的运行时和测试依据。

## 首个开发批次：性能体检与卡顿优化

### 批次目标

该批次只处理两类底层质量问题：

- 证明未启用功能不会留下隐性运行成本。
- 定位并优化顶部、底部、按屏、页面进度条、书签和目录跳转之间的滚动动画竞争与卡顿。

该批次不改变用户可见功能开关、不新增设置项、不新增权限、不新增远程日志或遥测字段。所有行为变化都应体现为更少的重复监听、更稳定的动画和更明确的测试覆盖。

### 前置工程卫生

开发前必须先将本文件保留在当前 worktree 的 `doc/` 下，作为本批次改动依据。后续排查、代码评审和回归记录均以当前 worktree 内的文档为准，不依赖其他路径下的历史副本。

## 功能一：设置页减负

### 产品目标

当前设置页已经承载基础按钮、页面进度条、按屏跳转、滚动位置书签、智能段落跳转、自动滚屏、图标、自定义颜色、站点管理、反馈、关于插件和多语言等内容。v2.5 应降低用户首次进入设置页时的认知负担。

首版只做两类低风险能力：

- 高级功能分组折叠。
- 恢复默认。

### 高级功能分组折叠

设置页应保留现有详细配置能力，但默认更容易浏览：

```text
基础设置
  滚动速度 / 按钮位置 / 尺寸 / 形状 / 间距 / 颜色 / 透明度

高级功能
  页面进度条       [展开/折叠]
  按屏跳转         [展开/折叠]
  滚动位置书签     [展开/折叠]
  智能段落跳转     [展开/折叠]
  自动滚屏         [展开/折叠]
  按钮图标         [展开/折叠]
```

行为规则：

- 折叠只影响设置页显示，不改变任何功能启用状态。
- 折叠状态保存在 `chrome.storage.local`，不进入同步设置。
- 首次打开设置页时，可以默认折叠高级功能详情，但应展示每个模块的名称和简短状态摘要。
- 如果用户从 Popup 或站点状态入口跳转到某个高级模块，应自动展开目标模块。
- 搜索设置项不纳入 v2.5 首版范围，可作为后续增强。

### 恢复默认

恢复默认分为全局恢复和模块恢复，避免用户为了修复一个配置误清所有设置：

```text
恢复默认
  [恢复基础按钮默认]
  [恢复页面进度条默认]
  [恢复按屏跳转默认]
  [恢复滚动位置书签默认]
  [恢复智能段落跳转默认]
  [恢复自动滚屏默认]
  [恢复全部同步设置默认]
```

规则：

- 恢复默认只重置 `chrome.storage.sync` 中的详细设置。
- 不清空 `chrome.storage.local` 中的主域名启停状态、书签、评分提示状态、统计 consent 或待上传统计队列。
- 恢复前必须展示确认，不应一键误触立即清空。
- 恢复后应立即刷新设置页预览，并通知已打开页面按新设置更新。
- 默认值必须与 `content.js`、`options.js`、`options.html` 和测试夹具保持一致。

## 功能二：兼容性增强

### 产品目标

继续提升文档类 SPA 和自定义滚动容器下的稳定性，重点覆盖：

- Notion。
- 飞书 Wiki / 飞书文档。
- 语雀。
- 钉钉文档。
- 其他使用自定义滚动容器、虚拟列表、延迟挂载正文或 SPA 路由切换的网站。

### 优化方向

- 滚动容器检测：继续保留 `document.scrollingElement`、候选容器评分和根元素回退逻辑。
- SPA 生命周期：路由变化、正文延迟出现和主要滚动容器替换时，按需重新解析容器。
- 动态内容：避免目录、进度和书签在内容高度变化后使用过期坐标。
- 自定义滚动容器：顶部/底部、按屏、进度条点击、书签恢复、目录跳转和自动滚屏应复用同一坐标体系。
- 站点禁用：当前主域名关闭插件或关闭某项高级功能时，应立即清理对应 DOM 和监听器。

### 兼容性测试建议

新增或扩展测试夹具时，应覆盖：

- 根页面滚动。
- 内层容器滚动。
- `document.body` 延迟出现。
- SPA URL 变化但页面不刷新。
- 滚动容器被替换。
- 内容高度在初始化后增加。
- 当前容器不可滚动后回退到新的主要容器。

真实浏览器验收时，不应把普通 `file://` 页面结果当作扩展运行结果。需要视觉或运行时验证时，应加载仓库根目录的未打包扩展。

## 功能三：性能体检

### 产品目标

v2.5 应确认所有默认关闭或当前主域名未启用的高级功能不会产生隐性运行成本。

重点检查：

- 页面进度条关闭时，不创建进度 DOM 或进度专属监听。
- 按屏跳转关闭时，不创建按屏按钮或命令以外的内容脚本状态。
- 滚动位置书签关闭时，不创建书签按钮、菜单、恢复提示或自动恢复检查。
- 智能段落跳转关闭时，不扫描标题、不缓存目录、不挂章节高亮监听。
- 自动滚屏关闭时，不启动 `requestAnimationFrame`、定时器或播放状态监听。

### 技术要求

- 初始化、storage 更新、站点状态变化、SPA 路由变化和页面卸载都应走同一清理路径。
- 优先复用现有清理函数，例如 `removeButton()`、`unbindProgressContainer()`、`unbindOutlineHighlightUpdates()`、`unbindAutoScrollPauseListeners()` 和 `cancelScrollAnimation()`；本批次定位是补齐清理缺口，不重写生命周期框架。
- 重复启停不产生重复 DOM、重复监听器、重复 MutationObserver 或重复动画循环。
- MutationObserver 只在必要阶段开启，成功初始化或功能关闭后按需断开。
- 滚动事件处理应节流或使用已有轻量更新路径，避免在高频滚动中扫描正文。
- 页面进度条的 RAF 更新属于轻量 UI 同步，可以在滚动期间逐帧执行；目录高亮、正文扫描和容器探测属于高成本路径，不应与进度条使用同一节流策略。
- 任何性能检测日志都不应默认上报远程服务。

### 验收矩阵

| 状态 | 应保证 |
| --- | --- |
| 当前主域名插件总开关关闭 | 不创建 host、基础按钮、高级功能 DOM；断开 SPA Observer、定时器、动画帧 |
| 页面进度条关闭 | 无进度 DOM、无进度专属 scroll listener、无进度 RAF |
| 按屏跳转关闭 | 无上一屏 / 下一屏按钮；不保留按屏动画容器状态 |
| 滚动位置书签关闭 | 无书签按钮、菜单、恢复提示；不执行自动恢复检查 |
| 智能段落跳转关闭 | 不扫描标题、不缓存目录、不绑定章节高亮 scroll listener |
| 自动滚屏关闭 | 不绑定暂停监听器，不启动 RAF，不保留 playing / paused 状态 |
| 任一高级功能反复开关 10 次 | DOM、listener、Observer、timer、RAF 数量不持续增长 |

### 测试要求

- 扩展 `tests/test-content-enable-state.js`，统计 DOM、document/window/storage listener、MutationObserver、timer 和 RAF 的基线与反复启停后的数量。
- 扩展 `tests/test-progress-bar.js`，证明页面进度条关闭时不绑定进度 scroll listener，不调度进度 RAF。
- 扩展 `tests/test-outline-navigation.js`，证明目录关闭时不扫描标题，关闭菜单时 DOM 变化只做失效标记，不重建快照。
- 扩展 `tests/test-auto-scroll.js`，证明自动滚屏停止或关闭后没有活动 RAF，暂停监听器不会重复绑定。

### 验收标准

- 高级功能全部关闭时，页面只保留基础滚动按钮相关 DOM 和监听。
- 当前主域名插件总开关关闭时，不创建任何页面按钮和高级功能 DOM。
- 反复切换任一高级功能 10 次后，DOM 数量和监听行为不持续增长。
- 自动滚屏停止或关闭后，不再持有活动动画帧。
- 智能段落跳转关闭后，不执行标题扫描或章节高亮计算。

## 功能四：卡顿优化

### 产品目标

优化部分页面回到顶部、回到底部和平滑滚动过程中的小卡顿，尤其是长文档、自定义滚动容器、动态内容和高刷新率设备上的体验。

本功能不以改变用户已保存的滚动速度设置作为替代方案。优化应尽量保持现有滚动速度语义，只在极端卡顿后做有限位移保护。

### 可能原因

实施前应先定位具体卡顿来源，不直接改动滚动曲线：

- 单帧滚动距离过大。
- 高频滚动事件触发进度、目录、书签或自动滚屏联动更新。
- 每次滚动都重新计算昂贵 DOM 信息。
- 自定义滚动容器检测在滚动过程中被重复触发。
- 动态内容或虚拟列表导致目标高度变化。
- 平滑滚动动画没有取消旧动画，多个动画竞争同一容器。
- `smoothScrollTo()` 调用链路中残留“每次操作前重新评估滚动容器”的热路径，和本批次的滚动动画统一入口互相覆盖。

### 优化方向

- 顶部、底部、按屏、进度条点击、书签恢复和目录跳转应统一通过同一滚动动画入口，新的滚动动作开始前取消旧的未完成动画。
- 统一动画入口前，先排查 `smoothScrollTo()` 调用链路上是否还存在残留的容器重新评分或全页面候选扫描；如果存在，应作为本批次前置清理项处理，避免和后续兼容性增强批次互相覆盖。
- 对进度更新、章节高亮和按钮状态刷新做轻量合并。
- 进度条 RAF 更新可继续保持逐帧，以保证滚动期间显示跟手；目录高亮、正文扫描和容器探测不应在每一帧执行。
- 在滚动动画期间避免重复扫描正文、标题或全页面候选容器。
- 对超长距离滚动增加稳定的帧间位移控制，避免卡顿后突然跳跃。
- 单帧位移保护允许极端卡顿时动画轻微拉长，但应设置上限。建议拉长不超过原定滚动时长的 1.5 倍；超过上限后放弃位移保护并直接收敛到目标位置，避免产生“滚动明显变慢”的新违和感。
- 对根页面和自定义滚动容器分别验证，不假设 `window` 是唯一滚动容器。
- 保持用户配置的滚动速度语义，不把卡顿优化变成默认速度大幅变化。

### 到底部动态高度处理

“回到底部”在动态内容增加、虚拟列表加载或文档后台恢复后最容易出现旧目标失效。安全刷新规则应明确：

- 不应在动画中检测到 `scrollHeight` 变化后取消并重启整段动画；这会造成二次加速度突变。
- 动画进行中可以按固定间隔低频轮询 `scrollHeight`，建议约每 200ms 一次。
- 若目标是底部且滚动范围增加，应重新计算目标位置，并把新增距离追加到当前动画的剩余距离中。
- 追加剩余距离不应重置整段动画进度，也不应让滚动方向反向跳动。
- 动画结束后可做一次最终校验，确保动态增长后的底部目标已经收敛。

### 测试要求

- 新增 `tests/test-scroll-animation-performance.js` 或扩展现有测试，只覆盖跨入口动画取消、位移保护和动态到底部目标刷新。
- 新测试应聚焦顶部、底部、进度条、书签、目录等不同入口互相打断时只保留最后一次动画。
- 自动滚屏自身的播放、暂停和停止行为继续保留在 `tests/test-auto-scroll.js`，避免一个专项测试文件覆盖过多职责。
- 扩展 `tests/test-progress-bar.js`，明确进度条更新频率应保持逐帧，不与目录高亮或容器探测使用同一节流策略。

### 验收标准

- 顶部、底部、按屏、进度条点击、书签恢复和目录跳转不会互相叠加旧动画。
- 新动作取消旧动画后，旧动画的 `onComplete` 不应继续触发目录高亮、进度刷新或后续跳转。
- 长页面顶部/底部跳转过程中没有明显重复停顿。
- 动态内容页面不会因为高度变化产生反向跳动。
- 自定义滚动容器中的滚动目标仍然准确。
- 优化不改变用户已保存的滚动速度设置。

## 隐私与权限

- v2.5 不因设置页折叠、恢复默认、兼容性增强、性能体检或卡顿优化而新增 Chrome 权限。
- 兼容性增强和性能体检不上传页面 URL、页面标题、页面内容、目录标题、书签内容或滚动位置。
- 恢复默认不清空本地隐私相关选择，例如匿名统计 consent 和评分提示状态。
- 如果后续要为性能问题新增遥测或错误码，必须单独确认 allowlist、用户文案、隐私披露和商店数据说明。

## 建议实施顺序

### 批次一：性能体检与卡顿优化

1. 同步并确认当前 worktree 内的 v2.5 方案文档。
2. 补性能体检测试，覆盖高级功能关闭、主域名关闭和反复启停 10 次不增长。
3. 排查 `smoothScrollTo()` 调用链路上是否存在残留容器重评估、全页面候选扫描或昂贵 DOM 查询热路径。
4. 明确进度条 RAF、目录高亮和容器探测的节流边界，保留进度条逐帧轻量更新。
5. 统一滚动动画入口：新动作开始前取消旧动画，旧动画完成回调不得继续生效。
6. 增加单帧位移保护，极端卡顿时允许有限拉长，但不超过原定时长 1.5 倍。
7. 对“回到底部”增加动态高度安全刷新：低频轮询 `scrollHeight`，将新增距离追加到剩余距离，不取消重启整段动画。
8. 跑对应 Node 回归测试和 `git diff --check`。未收到发布要求时不运行 `node build.js`，不生成 `dist/` 发布产物。

### 后续批次

1. 建立 v2.5 默认值、设置页折叠状态和恢复默认 helper。
2. 实现高级功能分组折叠、模块恢复默认和全部同步设置恢复默认。
3. 扩展 Notion、飞书、语雀、钉钉文档等文档类 SPA 的测试夹具和真实浏览器验收清单。
4. 更新 README、CHANGELOG、商店资料和发布检查清单。

## v2.5 完成定义

v2.5 只有在以下条件满足时才算完成：

- 设置页高级功能可以折叠和展开，恢复默认不会误清主域名状态、书签、统计 consent 或评分提示状态。
- Notion、飞书、语雀、钉钉文档等文档类 SPA 的滚动容器、顶部/底部、按屏、进度、书签、目录和自动滚屏路径没有明显回退。
