# v1.9 滚动位置书签产品需求文档

本文档定义 Page Scroll Master v1.9 内「滚动位置书签」功能的产品边界、数据结构、交互规则、风险控制和验收标准。本文档优先级高于旧版 `doc/v1.9-reading-feedback-spec-zh.md` 中关于滚动位置书签的早期设想。

> 2026-06-08 修订：滚动位置书签不再挂载到统一「阅读工具」入口中。当前设计将滚动位置书签和智能段落跳转拆为两个独立高级功能模块；滚动位置书签默认关闭，开启后显示独立书签按钮和书签菜单。旧版 `readingTools.*` 字段仅作为兼容迁移来源，新保存结构以 `scrollBookmarks.*` 为准。
>
> 2026-06-09 修订：新增书签加载方式设置。用户可选择再次打开页面时自动加载到最新匹配书签、仅显示恢复提示或仅通过书签菜单手动加载。

## 版本结论

v1.9 可以交付滚动位置书签功能，但必须把产品承诺限定为「回到大约阅读进度」，而不是「精确回到原内容块」。

核心定位：

- 百分比恢复优先。
- 默认不自动跳转，仅提示用户；用户可主动改为自动加载。
- 降低精确性承诺。
- 默认仅手动保存，不做后台自动记录。
- 复杂匹配与校正能力后置到 v1.9.1。

## 用户问题

用户在长文档、教程、文章、问答页或知识库页面中，常常需要稍后继续阅读。浏览器自带历史记录只能回到页面，不能帮助用户记住上次阅读进度。

本功能帮助用户在需要时手动保存当前滚动位置，并配置再次打开同一页面时的加载方式。

## 目标用户

- 经常阅读长技术文档的用户。
- 需要分多次阅读文章、教程、Wiki、问答页的用户。
- 使用 Page Scroll Master 浮动按钮进行长页面导航的用户。

## 非目标

以下能力不纳入 v1.9：

- 自动保存每个页面的阅读位置。
- `pathname-only` 匹配模式。
- 快捷键保存和快捷键自定义。
- 快捷键冲突检测。
- 容器 `selector/domPath` 相似度匹配算法。
- 恢复后的二次滚动校正。
- 基于保存天数的内容过期提示。
- 云同步、跨设备同步或账号体系。
- 上传 URL、标题或书签数据到远程服务。
- 将 V2.0 智能段落跳转本体提前到 v1.9。

## V1.9 交付范围

v1.9 交付以下 8 项：

1. 精确 URL 匹配，并将 hash 单独存储。
2. 内置追踪参数白名单归一化，不暴露 UI 开关。
3. 手动保存：通过独立「滚动位置书签」按钮打开菜单后触发「保存当前位置」。
4. 同一页面多次保存时默认覆盖旧记录，并显示更新提示。
5. 页面再次打开后按配置自动加载、显示 Toast 提示或仅保留手动加载入口。
6. 保存容器全量特征，恢复时使用简化策略。
7. 设置页新增「已保存位置」管理列表。
8. 存储上限：默认每域名 1 条，可选每域名最近 3 条；全局上限 300 条。

## V1.9.1 延后范围

以下能力建议放到 v1.9.1：

- `pathname-only` 匹配模式，放在高级设置中。
- 快捷键保存、快捷键关闭、自定义和冲突提示。
- 容器 `selector/domPath` 相似度匹配算法。
- 恢复后轻量二次校正。
- 内容过期或动态变化额外提示。

## 默认设置

新增设置建议拆分为公共入口模块和功能子模块，使用 `chrome.storage.sync` 保存配置。

```js
readingTools: {
  enabled: false,
  buttonPosition: 'pageBottom',
  buttonColorMode: 'followTopButton',
  buttonCustomColor: '#4A9EDD',
  features: {
    scrollBookmarks: true,
    outlineNavigation: false
  }
},
scrollBookmarks: {
  matchMode: 'exact',
  perDomainLimit: 1,
  globalLimit: 300,
  restoreMode: 'prompt'
}
```

字段说明：

- `readingTools.enabled`：是否显示阅读工具入口，默认关闭。
- `readingTools.buttonPosition`：阅读工具按钮在页面中的垂直位置，默认 `pageBottom`。
- `readingTools.buttonColorMode`：阅读工具按钮颜色模式，沿用阅读进度条的颜色设置思路。
- `readingTools.buttonCustomColor`：当 `buttonColorMode = 'custom'` 时使用的自定义颜色。
- `readingTools.features.scrollBookmarks`：是否在阅读工具中启用滚动位置书签能力。v1.9 默认跟随 `readingTools.enabled` 开启。
- `readingTools.features.outlineNavigation`：是否在阅读工具中启用智能段落跳转能力。v1.9 固定为 `false`，v2.0 再开放。
- `scrollBookmarks.matchMode`：v1.9 只支持 `exact`，预留给 v1.9.1 的 `pathname`。
- `scrollBookmarks.perDomainLimit`：每个域名保留的记录数，可选值为 `1`、`2` 或 `3`，默认 `1`。
- `scrollBookmarks.globalLimit`：全局记录上限，默认 `300`。
- `scrollBookmarks.restoreMode`：再次打开页面时的加载方式，可选 `auto`、`prompt` 或 `manual`，默认 `prompt`。

当前版本不提供自动保存模式、保留天数设置和快捷键设置。

## 阅读工具模块

v1.9 新增「阅读工具」模块，用于统一管理页面阅读工具入口。滚动位置书签是该模块下的第一个子功能；v2.0 智能段落跳转也挂载到同一个模块中。

阅读工具模块负责：

- 是否显示阅读工具按钮。
- 阅读工具按钮位置。
- 阅读工具按钮颜色。
- 阅读工具菜单结构。

滚动位置书签子功能负责：

- 保存当前位置。
- 恢复提示。
- URL 匹配。
- 存储上限。
- 已保存位置管理。

智能段落跳转子功能负责：

- 页面目录。
- 上一段、下一段。
- 当前章节高亮。

v1.9 不实现智能段落跳转本体，但应预留 `readingTools.features.outlineNavigation = false`。

### 产品原则

- 不使用顶部/底部按钮长按作为主入口。
- 不在页面上新增多个分散按钮。
- 阅读工具按钮复用现有按钮体系，但允许独立选择页面顶部、页面底部或上/下按钮之间。
- 阅读工具模块由用户自定义启用，默认不开启。
- 用户未启用阅读工具模块时，不显示阅读工具按钮。
- v1.9 中，阅读工具按钮只提供书签相关动作；v2.0 开启智能段落跳转后，同一个按钮扩展目录相关动作。

### 位置设置

用户可以在设置页选择阅读工具按钮位置。

设置项：

```js
buttonPosition: 'pageTop' | 'pageBottom' | 'betweenScrollButtons'
```

默认值：

```js
buttonPosition: 'pageBottom'
```

位置选项：

- `pageTop`：页面顶部，同侧边缘显示。
- `pageBottom`：页面底部，同侧边缘显示。
- `betweenScrollButtons`：上/下按钮之间，加入现有滚动按钮组。

阅读工具按钮的左右侧跟随当前上/下按钮的水平位置设置：

- 上/下按钮在右侧边缘时，阅读工具按钮也在右侧边缘。
- 上/下按钮在左侧边缘时，阅读工具按钮也在左侧边缘。

这允许用户实现类似布局：

```text
右侧中部：上/下按钮
右侧底部：阅读工具按钮
```

或：

```text
右侧中部：上/下按钮
右侧顶部：阅读工具按钮
```

如果用户启用了纵向阅读进度按钮，且 `readingTools.buttonPosition = 'betweenScrollButtons'`，阅读工具按钮应显示在进度按钮下方、向下按钮上方：

```text

```

位置、尺寸和行为规则：

- 左/右边缘位置。
- 边缘距离。
- 按钮尺寸。
- 按钮形状。
- 按钮间距。
- 透明度。
- 全屏隐藏。
- 站点禁用移除。

说明：

- `pageTop` 和 `pageBottom` 不跟随上/下按钮的顶部/居中/底部垂直对齐，而是分别固定在页面顶部或页面底部。
- `betweenScrollButtons` 跟随现有上/下按钮组的垂直对齐。
- `pageTop`、`pageBottom` 的顶部/底部边缘距离使用当前按钮边缘距离设置。
- `betweenScrollButtons` 的间距使用当前按钮间距设置。
- 阅读工具按钮的尺寸、形状、透明度、图标样式跟随当前上/下按钮设置。

### 颜色设置

阅读工具按钮颜色设置模式与当前阅读进度条一致，支持跟随和自定义。

设置项：

```js
buttonColorMode: 'followTopButton' | 'followBottomButton' | 'custom'
buttonCustomColor: '#4A9EDD'
```

建议默认：

```js
buttonColorMode: 'followTopButton'
```

规则：

- `followTopButton`：跟随顶部按钮颜色。
- `followBottomButton`：跟随底部按钮颜色。
- `custom`：使用 `readingTools.buttonCustomColor`。

### 位置避让

当 `readingTools.buttonPosition = 'betweenScrollButtons'` 时，阅读工具按钮会增加按钮组总高度。实现时应以整个按钮组为单位计算位置，确保最上方或最下方按钮不会超出视口。

不得让新增按钮覆盖原本的底部按钮，也不得让按钮组超出视口底部。

当 `readingTools.buttonPosition = 'pageTop'` 或 `pageBottom` 时，阅读工具按钮是同侧边缘上的独立入口，不改变现有上/下按钮组的垂直位置。

如果阅读工具按钮与上/下按钮组处于同侧且同为页面顶部或页面底部，应自动避让：

- 上/下按钮组位置优先保持不变。
- 阅读工具按钮负责偏移，避免覆盖上/下按钮组。
- 当 `readingTools.buttonPosition = 'pageBottom'` 且上/下按钮组也在同侧底部时，阅读工具按钮自动上移。
- 当 `readingTools.buttonPosition = 'pageTop'` 且上/下按钮组也在同侧顶部时，阅读工具按钮自动下移。
- 偏移距离应按上/下按钮组高度、当前按钮间距和边缘距离计算。
- 小屏幕或超大按钮导致空间不足时，阅读工具按钮不得覆盖上/下按钮，可临时隐藏或折叠。

示例：上/下按钮在右侧底部，阅读工具按钮也设置为页面底部时：

```text
右侧：
┌──────┐
│  🔖  │  阅读工具按钮，自动上移避让
└──────┘

┌──────┐
│  ▲   │
└──────┘

┌──────┐
│  ▼   │  上/下按钮组，保持底部位置
└──────┘
```

### 按钮图标

v1.9 图标建议使用书签语义：

```text
🔖 / bookmark outline
```

实际实现应优先使用现有 SVG 图标体系，避免依赖 emoji 渲染。

v2.0 开启智能段落跳转后，该按钮可以继续使用统一的「阅读工具」语义图标，或在展开菜单中用子项区分「保存位置」和「页面目录」。

### 点击行为

点击阅读工具按钮后显示轻量菜单。

v1.9 中，当 `readingTools.features.scrollBookmarks = true` 时显示书签菜单项：

```text
保存当前位置
加载已保存位置
```

规则：

- 点击「保存当前位置」立即保存当前页面位置。
- 点击「加载已保存位置」在当前页面手动恢复匹配书签；没有匹配记录时显示明确提示。
- 如果当前页面已保存过位置，「保存当前位置」仍显示，点击后覆盖旧记录。
- 菜单点击外部区域后关闭。
- 菜单不得遮挡顶部/底部按钮的点击区域。
- 如果所有子功能都关闭，阅读工具按钮不显示。

v2.0 中，当 `readingTools.features.outlineNavigation = true` 时，同一个菜单可扩展：

```text
保存当前位置
加载已保存位置
页面目录
上一段
下一段
```

v1.9 不实现目录、上一段、下一段，只保留入口结构兼容性。

## 存储结构

书签记录使用 `chrome.storage.local`，不要写入 `chrome.storage.sync`。

```js
bookmarks: {
  'exact:https://example.com/docs/api#section-2': {
    url: 'https://example.com/docs/api?utm_source=newsletter#section-2',
    normalizedUrl: 'https://example.com/docs/api#section-2',
    matchMode: 'exact',
    domain: 'example.com',
    pathname: '/docs/api',
    title: 'API Reference',
    scrollPct: 0.64,
    scrollY: 1840,
    savedAt: 1748650000,
    container: {
      isScrollingElement: false,
      tagName: 'DIV',
      overflowY: 'scroll',
      selector: '#app',
      domPath: 'body > div#root > div#app',
      scrollHeight: 28600,
      clientHeight: 900
    }
  }
}
```

字段规则：

- `url`：原始 URL，用于管理页展示和打开页面。
- `normalizedUrl`：去除追踪参数后的干净 URL，用于匹配索引。
- `matchMode`：v1.9 固定为 `exact`。
- `domain`：用于按域名限额和管理页展示。
- `pathname`：为后续 `pathname-only` 预留。
- `title`：保存时的 `document.title`，用于管理页展示。
- `scrollPct`：核心恢复字段，范围 `0-1`。
- `scrollY`：备用字段；当高度明显漂移时不使用旧 `scrollY`。
- `savedAt`：毫秒时间戳。
- `container`：保存滚动容器特征。v1.9 只使用稳定子集恢复，其余留给后续相似度匹配。

## URL 归一化规则

v1.9 使用精确 URL 匹配，但会删除纯追踪参数，避免同一内容因营销参数产生重复记录。

### 删除

删除以下参数：

```text
utm_source
utm_medium
utm_campaign
utm_content
utm_term
fbclid
gclid
mc_cid
mc_eid
```

同时删除所有 `utm_` 前缀参数。

### 保留

保留所有其他参数，包括但不限于：

```text
page
sort
filter
lang
tab
id
ref
source
```

理由：

- `page`、`sort`、`filter`、`tab` 可能代表不同内容状态。
- `lang` 可能代表不同语言内容。
- `id` 可能代表具体内容对象。
- `ref`、`source` 在部分网站上可能影响内容来源，v1.9 不删除，避免误合并。

### Hash

带 hash 的 URL 单独存储，不与无 hash 或其他 hash 合并。

示例：

```text
https://example.com/docs/api
https://example.com/docs/api#intro
https://example.com/docs/api#section-2
```

以上三者是三条不同记录。

### Key 生成

```js
const bookmarkKey = `${matchMode}:${normalizedUrl}`;
```

v1.9 的 `matchMode` 固定为 `exact`。

## 保存行为

### 入口

v1.9 只提供一个页面内保存入口：

- 阅读工具按钮菜单中的「保存当前位置」。

v1.9 不提供默认快捷键。

### 保存条件

满足以下条件时允许保存：

- `readingTools.enabled = true`。
- `readingTools.features.scrollBookmarks = true`。
- 当前页面存在可滚动区域。
- 当前滚动进度大于 0，且页面内容高度大于视口高度。
- 当前 URL 可被标准 URL API 解析。

### 保存成功提示

首次保存：

```text
已保存当前位置 64%
```

同一记录被覆盖：

```text
已更新位置到 72%（原 64%）
```

提示应短暂显示，不阻塞页面操作。

### 同页多次保存

同一个 `bookmarkKey` 多次保存时默认覆盖旧记录。

覆盖后：

- 更新 `scrollPct`、`scrollY`、`title`、`savedAt`、`container`。
- 显示新旧百分比变化。
- 不创建重复记录。

## 页面再次打开时加载

加载方式：

- `auto`：自动加载到当前页面最新匹配书签位置。
- `prompt`：显示恢复 Toast，由用户决定是否加载，默认值。
- `manual`：不自动加载且不显示提示，仅通过书签菜单手动加载。

### 触发时机

页面加载后查找当前 `normalizedUrl` 是否存在书签记录。

满足以下条件才执行自动加载或显示 Toast：

- `readingTools.enabled = true`。
- `readingTools.features.scrollBookmarks = true`。
- `scrollBookmarks.restoreMode` 为 `auto` 或 `prompt`。
- 当前页面存在匹配记录。
- 当前页面可滚动。
- 当前滚动位置未明显接近保存位置。

`auto` 模式在滚动容器暂未就绪时进行有限重试；`prompt` 模式显示以下 Toast。

### Toast 文案

```text
从大约 64% 处继续？
```

按钮：

```text
继续
忽略
```

规则：

- Toast 倒计时 5 秒后自动消失。
- 倒计时消失不执行恢复。
- 点击「忽略」后，本次页面生命周期不再提示。
- 文案必须使用「大约」，避免承诺精确位置。

## 恢复逻辑

### 容器识别

v1.9 保存容器全量特征，但恢复时使用简化策略：

1. 如果 `container.isScrollingElement = true`，直接使用 `document.scrollingElement`。
2. 否则查找当前页面中 `tagName` 和 `overflowY` 匹配的可滚动候选容器。
3. 如果无法可靠匹配，回退到 `document.scrollingElement`。
4. 最后兜底 `document.documentElement` 或 `document.body`。

v1.9 不使用 `selector` 和 `domPath` 做相似度匹配，但保留这些字段给 v1.9.1。

### 高度漂移判断

定义常量：

```js
const CONTAINER_HEIGHT_DRIFT_THRESHOLD = 0.2;
```

含义：

- 当前 `scrollHeight` 与保存时 `container.scrollHeight` 的差异超过 20% 时，认为页面高度明显漂移。
- 该阈值不是精确结论，应在 5 个典型站点测试后校准。

建议测试站点：

- MDN
- 飞书
- Notion
- 知乎
- 掘金

### 目标位置计算

恢复时优先使用百分比：

```js
targetY = saved.scrollPct * currentScrollableRange;
```

其中：

```js
currentScrollableRange = container.scrollHeight - container.clientHeight;
```

规则：

- 高度未明显漂移时，`scrollPct` 和 `scrollY` 都可作为参考，但仍推荐优先百分比。
- 高度明显漂移时，弃用旧 `scrollY`，仅使用 `scrollPct` 计算目标位置。
- `targetY` 必须被 clamp 到 `0-currentScrollableRange`。
- 调用现有 `smoothScrollTo()` 执行滚动。

v1.9 不做二次校正。

## 存储上限与淘汰

### 按域名上限

默认每个域名保留最新 1 条。

用户可在设置页选择：

```text
每个站点保留：最新 1 条 / 最近 2 条 / 最近 3 条
```

超出时按 `savedAt` 淘汰最旧记录。

### 全局上限

全局最多保存 300 条。

当全局记录超过 300 条时，按 `savedAt` 淘汰最旧记录。

建议顺序：

1. 保存新记录。
2. 按域名上限淘汰。
3. 按全局上限淘汰。
4. 写回 `chrome.storage.local.bookmarks`。

## 权限与隐私

本功能不得新增网络权限。

数据只保存在 `chrome.storage.local`：

- 保存 URL。
- 保存页面标题。
- 保存滚动百分比。
- 保存滚动容器特征。

不上传、不同步、不跨设备共享。

如果后续实现匿名统计，统计模块不得上传书签 URL、域名、标题、selector、domPath、滚动位置或页面内容。

## 风险与缓解

### 动态内容页误恢复

风险：同一 URL 的内容可能变化，百分比和像素都可能不再指向原内容。

缓解：

- Toast 使用「从大约 N% 处继续？」。
- 恢复优先百分比，不承诺精确内容。
- 高度明显漂移时弃用旧 `scrollY`。

### 容器识别失败

风险：SPA 路由切换、动态 class、虚拟列表会导致旧容器 selector 失效。

缓解：

- 保存全量容器特征。
- v1.9 只用稳定子集恢复。
- 失败时回退 `document.scrollingElement`。
- 复杂相似度匹配延后到 v1.9.1。

### URL 误合并或重复

风险：参数处理过宽会误合并不同内容，过窄会产生重复记录。

缓解：

- v1.9 只删除明确追踪参数。
- 其他参数全部保留。
- hash 单独存储。

### 设置页复杂度

风险：轻量插件设置页字段过多会压迫现有设置体验。

缓解：

- V1.9 只暴露阅读工具入口设置、滚动位置书签开关、每站保留数量、管理列表。
- 高级匹配、快捷键、过期提示不在 V1.9 暴露。
- 管理列表字段保持精简。
- 页面入口只新增一个阅读工具按钮，不为书签和目录分别新增常驻按钮。
- 阅读工具按钮只新增位置和颜色设置，其他视觉参数沿用当前按钮体系。

## 验收标准

### 功能验收

- 默认关闭时，不保存位置、不显示恢复 Toast、不改变现有浮动按钮体验。
- 开启「显示阅读工具按钮」并启用至少一个子功能后，页面显示独立阅读工具按钮。
- 仅开启智能段落跳转且关闭滚动位置书签时，不显示书签菜单项，不保存 URL、标题或滚动位置。
- 阅读工具按钮可设置为页面顶部、页面底部或上/下按钮之间。
- 阅读工具按钮左右侧跟随当前上/下按钮的左/右边缘设置。
- 上/下按钮在右侧边缘中部时，阅读工具按钮可以显示在右侧顶部或右侧底部。
- 上/下按钮在同侧顶部或底部时，阅读工具按钮设置到相同顶部或底部会自动避让，不覆盖上/下按钮。
- 阅读工具按钮颜色可设置为跟随顶部按钮、跟随底部按钮或自定义颜色。
- 选择上/下按钮之间且开启纵向阅读进度按钮时，阅读工具按钮显示在进度按钮下方。
- 点击阅读工具按钮可以打开阅读工具菜单。
- 启用滚动位置书签时，书签菜单包含「保存当前位置」和「加载已保存位置」。
- 点击「保存当前位置」可以保存当前位置。
- 保存成功后显示当前百分比。
- 同一页面再次保存会覆盖旧记录，并提示新旧百分比。
- `auto` 模式再次打开同一 `normalizedUrl` 后自动加载到最新匹配书签位置。
- `prompt` 模式再次打开同一 `normalizedUrl` 后显示恢复 Toast，倒计时消失时不自动恢复。
- `manual` 模式再次打开页面时不滚动、不显示恢复 Toast，书签菜单仍可手动加载。
- 点击「继续」后按百分比滚动到目标位置。
- 点击「忽略」后，本次页面生命周期不再提示。
- hash 不同的 URL 分别保存和恢复。
- 追踪参数不同但正文相同的 URL 可以匹配同一记录。
- 非追踪参数不同的 URL 不会被合并。
- 管理页可以查看、删除单条记录和全部清除。
- 每域名和全局上限淘汰逻辑生效。

### 兼容性验收

- 不新增网络权限。
- 不写入 `chrome.storage.sync` 作为书签数据存储。
- 不影响现有顶部、底部、进度条按钮。
- 阅读工具按钮不会覆盖顶部、底部、进度条按钮。
- 阅读工具按钮跟随当前上/下按钮的左/右边缘位置、尺寸、形状、间距、透明度、全屏隐藏和站点禁用逻辑。
- 阅读工具按钮颜色遵循独立颜色模式设置。
- 阅读工具按钮不新增独立间距、样式、尺寸或透明度设置。
- 不影响站点禁用逻辑。
- 全屏隐藏逻辑仍然生效。
- SPA 页面切换后不会重复注入 Toast。
