# v2.1 Product Experience & Privacy Update 产品规划

本文档定义 Page Scroll Master v2.1 的整体产品范围。v2.1 在 v2.0 长页面导航能力之上，补充站点级高级功能控制、新用户引导、版本更新记录和隐私友好的匿名使用统计。

匿名使用统计的详细边界见 `doc/v2.1-usage-analytics-spec-zh.md`，实施步骤见 `doc/v2.1-usage-analytics-implementation-plan-zh.md`。

## 版本目标

v2.1 聚焦四项能力：

1. 用户可直接在浏览器工具栏 Popup 中，按当前主域名控制整个插件和三项高级功能是否启用。
2. 新用户首次成功安装扩展后自动打开设置页，完成首次认知和配置。
3. 在设置页“建议&反馈”模块内新增“更新记录”，简要展示各版本主要新功能和优化项。
4. 在用户主动同意后采集匿名聚合使用统计，用于评估功能优先级和默认值。

## 非目标

以下能力不纳入 v2.1：

- 不支持在设置页控制页面进度条、滚动位置书签或智能段落跳转是否启用；设置页只配置三项高级功能的详细参数。
- 不支持按完整 URL、路径、标签页或页面规则配置高级功能。
- 不为主域名级高级功能设置增加云同步。
- 不在扩展升级、浏览器启动或普通重载时自动打开设置页。
- 不从远程服务加载更新记录。
- 不在用户未同意时上传匿名统计。
- 不提前实现 v3.0 的扩展内直接提交反馈服务。

## 功能一：Popup 按主域名启用插件和高级功能

> 开发状态（2026-06-11）：源码实现和对应 Node 回归已完成，包括公共后缀主域名解析、旧数据迁移、Popup 四开关、内容脚本即时启停、设置页启用入口移除及主域名状态管理。尚未执行真实 Chrome 加载后的 Popup/设置页视觉与交互验收。

### 产品目标

用户无需进入完整设置页，即可在当前网页对应的浏览器工具栏 Popup 中，控制整个插件以及页面进度条、滚动位置书签和智能段落跳转是否在当前主域名生效。

该能力用于处理不同网站的兼容性和使用场景差异。例如，用户可以在文档网站启用页面进度条和智能段落跳转，但在其他网站仅保留顶部、底部基础按钮。

设置页中的“高级功能”模块只负责详细参数配置，不再提供三项高级功能的启用开关。用户是否使用某项高级功能，统一由 Popup 中当前主域名对应的开关决定。

### 主域名规则

启用状态定义在主域名层级，不按完整 URL、路径、query、hash 或单个页面保存。

- `docs.example.com`、`app.example.com` 和 `www.example.com` 统一归入 `example.com`。
- 主域名应按可注册域名（effective top-level domain plus one，eTLD+1）解析，不能简单截取 hostname 最后两段，以免错误处理 `example.co.uk` 等公共后缀。
- IP 地址、`localhost` 和无法解析为可注册域名的开发环境 hostname 使用完整 hostname 作为站点键。
- `chrome://`、扩展页面、新标签页及其他内容脚本不可运行页面不生成站点键，也不保存状态。
- Popup、内容脚本和设置页域名管理必须复用同一套主域名标准化逻辑。

### Popup 交互

Popup 顶部提供当前主域名的插件总开关，并在其下提供三个高级功能开关。

建议结构：

```text
在此主域名启用插件                       [开]

高级功能
页面进度条                               [开]
滚动位置书签                             [关]
智能段落跳转                             [开]

[打开设置]
```

交互规则：

- Popup 根据当前活动标签页解析出的主域名读取和保存设置，并显示当前控制对象，例如 `当前网站：example.com`。
- 只允许在内容脚本可运行且能获得有效主域名或开发环境 hostname 的普通网页上修改。
- 插件总开关关闭时，三个高级功能开关显示为不可用，但保留各自已保存状态。
- 插件总开关开启后，用户可分别设置页面进度条、滚动位置书签和智能段落跳转是否在该主域名启用。
- 三项高级功能的启用入口只存在于 Popup；设置页中的对应模块不再显示启用复选框。
- Popup 修改后应立即通知当前标签页刷新对应功能，不要求用户手动刷新页面。

### 生效规则

每个高级功能的最终状态由当前主域名的插件总开关和对应功能开关共同决定：

```text
基础顶部/底部按钮启用 = 当前主域名的插件总开关开启

高级功能最终启用 = 当前主域名的插件总开关开启
                AND 当前主域名的对应高级功能开关开启
```

兼容原则：

- 插件总开关和三个高级功能开关是四个独立状态，不能复用同一个布尔值。
- 插件总开关关闭时，不创建基础按钮、高级功能 DOM 或相关监听器。
- 插件总开关重新开启时，恢复该主域名此前保存的三个高级功能状态。
- 新安装用户首次访问某主域名时，插件总开关默认开启，三个高级功能默认关闭。
- 旧用户升级时，应迁移已有 `enableStates` 和 `advancedSettings.*.enabled`，确保升级前已经启用的功能不会意外关闭；迁移完成后，启用状态不再由 `advancedSettings` 保存。
- 后续新增高级功能时，未出现在旧主域名记录中的功能默认关闭，等待用户在 Popup 主动开启。

### 存储建议

主域名级插件和高级功能启用状态属于站点数据，保存在 `chrome.storage.local`，不进入 `chrome.storage.sync`。详细参数继续保存在 `chrome.storage.sync`。

建议结构：

```js
domainFeatureStates: {
  'example.com': {
    extensionEnabled: true,
    features: {
      progressBar: true,
      scrollBookmarks: false,
      outlineNavigation: true
    }
  }
}
```

存储规则：

- 统一以标准化后的主域名作为 key，子域名和不同页面不得创建重复记录。
- 每条记录同时保存插件总开关和三个高级功能开关，便于 Popup 与域名管理读取同一事实来源。
- `advancedSettings.progressBar`、`advancedSettings.scrollBookmarks` 和 `advancedSettings.outlineNavigation` 只保存详细参数，不再保存 `enabled`。
- 删除某主域名记录后恢复新站点默认状态：插件开启，三个高级功能关闭。
- 不把主域名级状态加入匿名统计快照或事件 payload。

### 设置页管理

现有域名管理模块应升级为主域名功能状态列表。每行至少显示：

- 主域名。
- 插件是否启用。
- 页面进度条是否启用。
- 滚动位置书签是否启用。
- 智能段落跳转是否启用。
- 删除或重置该主域名记录的操作。

建议列表结构：

```text
域名            插件    页面进度条    滚动位置书签    智能段落跳转    操作
example.com     开      开            关              开              删除
notion.so       开      关            开              开              删除
news.example    关      关            关              关              删除
```

管理规则：

- 列表使用主域名展示和搜索，不展示完整 URL。
- 插件关闭时，三个高级功能列显示已保存状态但呈不可用样式，避免误认为状态已被清除。
- 可直接在列表中修改插件总开关和三个高级功能开关。
- 必须提供删除单个主域名记录和清除全部主域名记录的能力。
- 添加 URL 或子域名时，应先解析并显示将要保存的主域名，避免用户误以为规则只作用于当前子域名。

### 验收标准

- Popup 可以按当前主域名修改插件总状态和三个高级功能状态。
- 同一主域名下不同子域名和不同 URL 读取同一组状态。
- 设置页只配置三个高级功能的详细参数，不提供启用开关。
- 域名管理列表完整显示插件总状态和三个高级功能状态。
- 关闭插件总开关后不创建基础按钮、高级功能 DOM 或相关监听器。
- 修改主域名状态后当前页面立即更新，重复切换不产生重复 DOM 或监听器。
- 自定义滚动容器和 SPA 页面中的高级功能启停行为正确。
- 主域名信息仅保存在本地，不进入匿名统计。

## 功能二：新安装后自动打开设置页

> 开发状态（2026-06-13）：已按方案 A 实现，仅全新安装时自动打开设置页；“快速开始”仅对全新安装显示，用户确认后保持隐藏，并可从“关于插件”重新查看。已补充全语言文案和安装生命周期、Options、多语言 Node 回归。不新增 `management` 权限，也不监听浏览器扩展管理页中的禁用后重新启用。尚未执行真实 Chrome 加载后的视觉验收。

### 产品目标

让新用户在安装成功后立即看到功能说明、基础设置和高级功能入口，降低“安装后不知道如何配置”的问题。

### 触发规则

- 使用 `chrome.runtime.onInstalled` 监听安装事件。
- 仅当 `details.reason === 'install'` 时调用 `chrome.runtime.openOptionsPage()`。
- 扩展升级、Chrome 更新、浏览器启动、扩展重载和设置重置时均不自动打开。
- 用户在 `chrome://extensions` 中禁用后重新启用扩展时不自动打开；该行为需要高风险 `management` 权限，不纳入 v2.1。
- Popup 中按主域名关闭后重新启用扩展功能时不自动打开。
- 自动打开失败不能影响扩展安装和基础滚动功能。

### 设置页首屏要求

自动打开后使用现有默认标签页，不在设置页提供或强制开启任何高级功能，也不强制用户开启匿名统计。

“快速开始”仅在全新安装写入本地显示标记后出现；旧用户升级或缺少该标记时默认隐藏。用户点击“知道了”后保持隐藏，并可从“关于插件”主动重新查看。

首屏应让用户能够快速理解：

- 扩展的顶部、底部滚动核心功能。
- 如何打开浏览器工具栏 Popup。
- 高级功能由 Popup 按当前主域名启用，详细参数在设置页配置。
- 匿名统计默认关闭，需要用户主动开启。

### 验收标准

- 全新安装后自动打开一次设置页。
- 从旧版本升级到 v2.1 不自动打开设置页。
- 浏览器扩展管理页禁用后重新启用不自动打开设置页。
- 浏览器重启和扩展 service worker 重启不重复打开。
- 自动打开行为只写入本地引导显示标记，不修改功能设置。

## 功能三：建议&反馈中的更新记录

### 产品目标

让用户在扩展内快速了解当前版本和历史版本的主要变化，提高新功能可发现性，并减少用户必须前往 README 或商店页面查看版本信息的成本。

### 信息架构

在设置页“建议&反馈”标签内新增独立“更新记录”卡片，放在现有“关于插件”和联系方式卡片之后。

建议结构：

```text
更新记录

v2.1.0
- 新增按主域名控制插件和高级功能
- 新用户安装后自动打开设置页
- 新增扩展内更新记录
- 新增可选匿名使用统计

v2.0.0
- 新增智能段落跳转和页面大纲导航
- 优化长页面章节识别和跳转体验
```

展示规则：

- 更新记录从 `v1.8.0` 开始，不展示更早版本。
- 当前版本置顶，历史版本按版本号倒序排列。
- 当前版本默认展开，历史版本默认折叠；不保存用户的展开状态。
- 每个版本只使用“新功能”“功能优化”“Bug 修复”三类标题，没有内容的分类不显示。
- 默认展示每个版本 2 到 6 条用户可理解的最终变化。
- 不展示产品决策和方案调整过程，也不展示提交记录、内部重构、测试或构建调整等工程细节。
- 未发布版本可以随扩展代码预先维护，但设置页只渲染不高于 `manifest.json` 当前版本的记录，避免提前展示未发布功能。
- 当前版本号应与 `manifest.json` 一致。
- 文案应覆盖当前支持的所有 Options 语言。

### 数据与维护规则

- 更新记录随扩展包本地发布，不发送网络请求，不依赖远程 Markdown 或接口。
- `doc/CHANGELOG.md` 继续作为完整变更记录。
- 设置页更新记录是面向用户的简要摘要，不替代完整 Changelog。
- 每次版本发布时，同时更新 `manifest.json`、`README.md`、`doc/CHANGELOG.md` 和设置页更新记录。

### 验收标准

- “建议&反馈”内可以查看当前版本和主要历史版本摘要。
- 当前展示版本与 `manifest.json` 一致。
- 所有支持语言都有对应标题、版本摘要和交互文案。
- 更新记录在离线状态下可用，且不产生网络请求。
- 内容在窄窗口和长文本语言下仍可阅读。

## 功能四：隐私友好的匿名使用统计

> 开发状态（2026-06-13）：客户端本地聚合、同意开关、数据预览、事件接入、可选权限、定时上传和有界重试已实现；独立 Cloudflare Worker + D1 后端已部署，隐私政策和商店文案已更新。发布前仍需真实 Chrome Network 验证和 Chrome Web Store 后台数据披露复核。

### 产品目标

在用户主动同意后，采集不含页面上下文的匿名聚合事件，帮助评估核心设置分布、高级功能开关操作趋势和常用操作频率。

### 产品边界

- 默认关闭，新安装和升级用户均不发送统计。
- 不上传 URL、域名、页面标题、页面内容、站点启停列表或主域名级高级功能状态。
- 不生成长期用户 ID，不采集错误事件，不统计当前 Popup 中不存在的顶部/底部跳转操作。
- 关闭后立即停止采集和上传，并清理本地待发送队列。
- 详细事件、权限、保留期和验收规则以 `doc/v2.1-usage-analytics-spec-zh.md` 为准。

## 建议实施顺序

1. 新安装后自动打开设置页。
2. “建议&反馈”中的更新记录。
3. Popup 按主域名控制插件和高级功能，并升级设置页域名管理列表。
4. 匿名使用统计、隐私披露和服务端上传。

前两项依赖少，可先完成产品体验闭环；主域名级插件和高级功能控制需要同时修改 Popup、内容脚本和本地存储；匿名统计需要先确认服务端、权限和隐私合规。

## v2.1 完成定义

v2.1 只有在以下条件满足时才算完成：

- 四项产品能力均按各自验收标准实现。
- 旧用户升级后现有站点启停和高级功能行为通过一次性迁移保持一致。
- 新安装只自动打开一次设置页，不自动开启高级功能或匿名统计。
- 更新记录与发布版本一致，并完成全部支持语言覆盖。
- 主域名级插件和高级功能状态仅保存在本地，未进入匿名统计。
- 匿名统计默认关闭，代码行为、隐私政策和商店披露一致。
- 对应 Node 回归测试、真实扩展 Popup/设置页检查和浏览器 Network 检查通过。

> 发布收尾状态（2026-06-13）：`manifest.json`、README、CHANGELOG 和设置页版本已同步为 `2.1.0`；完整 `node build.js`、源码与打包后回归、ZIP 完整性和大小检查均已通过，生成 `dist/page-scroll-master-v2.1.0.zip`。当前自动化环境禁止访问 `chrome://extensions`，且固定统计端点连接超时，因此真实 Chrome Popup/Options/Network 验收和 Chrome Web Store 后台披露仍需人工完成。
